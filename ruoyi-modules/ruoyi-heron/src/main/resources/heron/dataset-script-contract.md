# Heron 数据看板脚本 JSON 创作契约

本文件是数据看板写稿的写死口径，对应 `docs/plans/2026-11-10-dataset-contract.md`。改这里等于改业务契约，需人工同步文档。

## 输出形态

只输出一个 JSON 对象，不带 Markdown 代码块、不带解释文字、不输出 HTML。

| 字段 | 必填 | 约束 |
|---|---|---|
| `dataset_sha256` | 系统覆盖 | 数据快照哈希，不必自己填 |
| `source_key` | 系统覆盖 | 数据源 key，不必自己填 |
| `chart` | 系统覆盖 | 由数据形态决定，不必自己填 |
| `title` | 是 | 屏幕标题，不超过 15 字 |
| `scenes` | 是 | 3–6 段，每段 `{lead, body, duration_s}` |
| `closing` | 是 | 结尾一句话 |
| `source_name` | 系统覆盖 | 画面「来源：xxx」文案，不必自己填 |

- 每段 `lead` ≤ 20 字、`body` ≤ 70 字、`duration_s` 为正数秒；全部段落合计 30–75 秒。
- 只允许上述字段。出现未知字段直接退回。

## 旁白规则（最重要）

1. **正文禁止出现任何阿拉伯数字**：包括年份、百分比、数量、排名。出现一个数字就退回。
2. 需要数字时只能写占位符 `{{facts.<路径>}}`，路径必须是输入 JSON 的 `facts` 下能解析到的标量。
3. 占位符不允许算术、函数或默认值，例如不能写 `{{facts.change + 1}}`。
4. 例：`金价收于 {{facts.last.value}} 美元，较前一日 {{facts.change}} 美元。`
5. 至少两段引用 `facts`，不要只写空泛形容。
6. 只描述输入数据里存在的事实，不补背景、不编原因、不预测。

## 写作风格

- 口语、短句、有信息增量；不复述图表标题，不念坐标轴。
- 开头一句给结论或反差，中段解释变化，结尾给一句判断或提醒。
- 不写「如图所示」「请看图表」这类空话。

## 数据形态与 chart

| `shape` | `chart` | 说明 |
|---|---|---|
| `wide` | `line` | 单指标时间序列 |
| `long` | `race` | 多实体时间序列 |
| `rows` | `bars` | 单期排行或对比 |
| `geo` | `map` | 地理分布 |
