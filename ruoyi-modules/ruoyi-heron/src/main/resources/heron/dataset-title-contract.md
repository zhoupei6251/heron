# 数据看板标题契约

## 输出形态

只输出一个 JSON 对象，不带 Markdown 围栏、不带解释文字：

```json
{"candidates":[{"kind":"数字反差","title":"..."},{"kind":"疑问悬念","title":"..."},{"kind":"利益相关","title":"..."},{"kind":"时间紧迫","title":"..."},{"kind":"反常识","title":"..."}]}
```

## 五类钩子，各一个

| kind | 要做的事 | 例子（只示范结构，不照抄） |
|---|---|---|
| 数字反差 | 用数据里的数字制造反差 | 跌了 {{facts.change}} 美元，谁在买 |
| 疑问悬念 | 把观众的问题问出来 | 金价掉头，底在哪 |
| 利益相关 | 点名谁该关心 | 手里有黄金的先看这个数 |
| 时间紧迫 | 给时间锚点 | 这周金价只看一个位置 |
| 反常识 | 结论与直觉相反但数据支持 | 金价在跌，反而不是坏事 |

## 硬约束

1. 每个标题解析占位符后 **4–15 字**。
2. 可以用 `{{facts.<路径>}}`，路径必须是 facts 下能解析的标量；不要自己编数字。
3. 涨跌方向必须与 `facts.change` 一致：负数不能说「涨/升/新高」，正数不能说「跌/降/新低」。
4. 禁止：必涨、必跌、稳赚、抄底、逃顶、预测、将涨、将跌、一定、保证。
5. 不堆标点、不用书名号、不写「震惊」「速看」这类标题党。
6. 五个标题必须互不相同，且都能被画面数据支撑。
