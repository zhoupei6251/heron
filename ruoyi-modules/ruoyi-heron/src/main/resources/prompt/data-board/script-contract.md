# Heron 数据看板脚本 JSON 创作契约

本文件是数据看板写稿的写死口径，对应 `docs/plans/2026-11-10-dataset-contract.md`。改这里等于改业务契约，需人工同步文档。

## 输出形态

只输出一个 JSON 对象，不带 Markdown 代码块、不带解释文字、不输出 HTML。

| 字段 | 必填 | 约束 |
|---|---|---|
| `dataset_sha256` | 系统覆盖 | 数据快照哈希，不必自己填 |
| `source_key` | 系统覆盖 | 数据源 key，不必自己填 |
| `chart` | 系统覆盖 | 由数据形态决定，不必自己填 |
| `title` | 是 | 屏幕标题，不超过 15 字 |
| `scenes` | 是 | 3–6 段，每段 `{lead, body, duration_s}` |
| `closing` | 是 | 结尾一句话 |
| `source_name` | 系统覆盖 | 画面「来源：xxx」文案，不必自己填 |

- 每段 `lead` ≤ 20 字、`body` ≤ 70 字、`duration_s` 为正数秒；全部段落合计 30–75 秒。
- 只允许上述字段。出现未知字段直接退回。

## 旁白规则（最重要）

1. **正文禁止出现任何阿拉伯数字**：包括年份、百分比、数量、排名。出现一个数字就退回。
2. 需要数字时只能写占位符 `{{facts.<路径>}}`，路径必须是输入 JSON 的 `facts` 下能解析到的标量。
3. 占位符不允许算术、函数或默认值，例如不能写 `{{facts.change + 1}}`。
4. 例：`金价收于 {{facts.last.value}} 美元，较区间起点变化 {{facts.change}} 美元。`
5. 至少两段引用 `facts`，不要只写空泛形容。
6. 只描述输入数据里存在的事实，不补背景、不编原因、不预测。
7. `facts.change` 与 `facts.change_pct` 是快照区间首值到末值的变化，起止日见 `facts.first.date/last.date`；不是单日或上一交易日涨跌。不得把区间变化写成「较前一日」「昨日」或「单日上涨/下跌」。

## 写作风格

- 口语、短句、有信息增量；不复述图表标题，不念坐标轴。
- 开头一句给结论或反差，中段解释变化，结尾给一句判断或提醒。
- 不写「如图所示」「请看图表」这类空话。

## 叙事结构（硬约束，违反退回）

数据异常不等于值得讲。先想清楚这条片子要讲什么，再动笔；没有故事就老实按数据速览写。

1. **前两屏必须有具体信息**：前两段（`scenes[0]`、`scenes[1]`）合计至少引用一个 `facts` 占位符。第一屏可以用问题或反差起手，但观众不能等到第三屏才拿到可验证的信息。
2. **开场不许先讲准备过程**：不得以「数据源」「数据快照」「据统计」「统计口径」「本栏目」「本期节目」「接下来我们看」开头。观众第一秒要拿到结论、反差或悬念。
3. **标题与开场互相配合，不许复读**：第一段 `lead` 不能包含标题原句；标题负责抓人，开场负责立刻兑现它。
4. **每段各司其职**：开场给结论或反差 → 中段用对比 / 变化 / 关键节点推进证据 → 有一处明显的重点（最异常的区间、最大差距、拐点）→ 结尾给判断、提醒或一个值得讨论的问题。不要每段都在平铺直叙同一件事。
5. **结尾要有信息**：禁止「持续关注」「感谢观看」「下期再见」「点赞收藏」这类空关注引导。
6. **至少两段引用 `facts`**：全程只有一段有数、其余都是形容，等于没讲数据。

不同题材换不同讲法：反常识、数字反差、趋势反转、排名竞争、关键节点、现象与影响的差异——按数据本身选，不要每条都用同一套。

## 数据形态与 chart

| `shape` | `chart` | 说明 |
|---|---|---|
| `wide` | `line` | 单指标时间序列 |
| `long` | `race` | 多实体时间序列 |
| `rows` | `bars` | 单期排行或对比 |
| `geo` | —— | 地图模块未实现，取数闸直接拒绝，不会走到写稿 |

`chart` 由系统按形态覆盖，不要自己填。渲染端只认 `line` / `bars` / `race`，映射不到可用模块的形态不会进生产。
