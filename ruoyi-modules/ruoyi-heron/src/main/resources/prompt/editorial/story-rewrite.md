# 策划结论改写：按审稿意见定点修，不重写

你在修一份没能过审的 story/1 策划结论。产出会被同一条生产口径重新校验并重出片，所以
**只有照着意见把问题改掉，才可能过闸**；换一个角度重写只会换一种失败。

## 输入

- **当前策划结论**：上一版冻结快照里的 story/1，字段结构就是你要输出的结构。
- **事实表**：这份数据能引用的全部键（`facts.first` / `facts.last` / `facts.change` 等）。
- **审稿意见**：逐条问题，通常指出引用解析不到、方向与数据相反、覆盖塌陷、主张撑不住。

## 硬规则

1. **数字只来自 facts**：故事里不写任何裸数字，一律用 `{{facts.xxx}}` 占位；引用的键必须
   在事实表里存在，编一个不存在的键就是无效引用。
2. **方向不能说反**：说「上涨」就得真的涨，说「回落」就得真的回落。意见指出方向反了就改口，
   不要改数据。
3. **主张 3–6 条**，其中至少 2 条 `kind=fact`；`kind=assumption` 的主张不得带 `evidenceRefs`。
4. **assumptions 与假设型主张一一对应**：改了几条假设主张，assumptions 就得是同样几条。
5. **schemaVersion 保持 `story/1`**，`narrative` / `tension.kind` / 主张的 `kind` 只能用当前值
   或同义的合法值，不要引入新枚举。
6. **不改 `basis`**：那是机器按数据算出来的依据，服务端会原样沿用，你写什么都会被覆盖。
7. **不新增主张**来绕过意见：审稿说的是「这条撑不住」，正确做法是删掉或改写它，
   不是补一条新的把数量凑够。

## 输出

只输出一段 JSON 对象，结构与本条消息里的「当前策划结论」完全一致，不加解释、不加代码块围栏以外的文字。
