# 三维可视化故事（3D Visual Storytelling）：传播实证与 Heron 落地建议

> 来源：2026-11 外部调研对话的蒸馏稿（原文含图片与外链，已剔除）。
> 文中播放量、粉丝量等数字来自第三方账号分析/案例库/研究报告的转述，**未经独立核验**，也不构成抖音全站排名；
> 各形式的"高/低"是选题判断，不是平台数据。引用前请自行复核。

## 一句话结论

**要加，但不要新造一条独立生产线。** 把 3D 定位成数据看板线之下的高级视觉表达模块：
Three.js 做主力、HyperFrames 负责整体编排、FFmpeg 收口合成，Blender 先只作为未来特殊资产工具，
且**不放在生产服务器上跑批量渲染**。先用 6~10 条视频做对照试验，没收益就不扩大投入。

## 核心判断：什么样的 3D 有传播力

真正有传播力的不是炫技的 3D，而是**把普通人看不见、想不到或难以理解的东西用三维呈现出来**。

一个可参考的方向性证据（第三方研究，样本 7,317 条 TikTok 3D 创作视频）：角色动画、
Blender 建模与场景展示的相对触达表现较突出，**纯 AI 生成 3D 内容反而较弱**。
另有 2026-10 的同类研究转述：Blender 场景视频的粉丝相对触达中位数约 8.6 倍、
角色动画约 9.1 倍，15 秒以内的视频优于更长视频。两项都不是抖音口径。

## 一、值得关注的六种形式

| # | 形式 | 典型选题 | 传播潜力 | Heron 适配度 |
|---|---|---|---|---|
| 1 | 极端假设 / 灾难与物理模拟 | 地球停转、月球靠近、小行星撞击、海平面上升 100 米、超级火山 | 很高 | 高 |
| 2 | 三维地理 / 世界地图 / 历史事件 | 海峡为何关键、五大航运路线、航道封锁影响、中国三级阶梯地形、石油与贸易流向 | 很高 | **极高** |
| 3 | 物体剖面 / 内部结构与机械原理 | 航空发动机内部、百层建筑受力、高铁运行、核电站、航母内部、地震中建筑受力 | 高 | 高 |
| 4 | 电影级历史与事件还原 | 罗马军团行军、古城鼎盛原貌、著名战役全过程、沉船前后、建筑兴毁 | 高 | 高 |
| 5 | 解压 / 流体与物理模拟 | 高空落体、水流过复杂结构、材料受撞、破碎坍塌、液体沙粒布料 | 高 | 低 |
| 6 | 3D 卡通角色连续短故事 | 果蔬拟人争吵、动物故事、荒诞冒险 | 很高 | 中低 |

**形式 1 的第三方数据**：Lunar Animation 账号（第三方账号分析记录）《What if the Earth stopped spinning?》
约 3,060 万播放、《What if the sun exploded?》约 1,850 万播放，10 条累计约 7,130 万。

**形式 2 的第三方数据**：「三维地图看世界」2023 年一项研究记录约 849 万粉丝、28.1 亿点赞
（**历史样本，不代表当前账号数据**）。这类内容在中文抖音已有长期受众基础。

**形式 6 的第三方数据**：果蔬角色动画约 1,430 万播放、稻鱼共生 3D 故事约 960 万播放（案例库转述）。
传播潜力不错，但需要稳定角色模型、动作、表情和故事线，**不是 Heron 当前优先方向**。

### 形式 3 真正值钱的地方

原本无法直接拍摄的内部结构，可以靠剖切、爆炸图、镜头穿透来展示——这是二维图表和实拍都给不了的。

### 形式 4 的红线

必须区分**考古证据 / 史料 / 艺术推演**，不能把想象画面当作真实记录。

## 二、三条最值得补的方向

排在最前的是 **A** 和 **B**，因为它们既有无限选题来源，又能吃上 Heron 现有的数据分析与 AI 策划能力。

- **A 全球数据与地理**：人口、经济、能源、贸易；地缘、航道、资源分布；国家城市地形与空间变化。
- **B 科学假设与事件模拟**：极端天气、地震海啸；地球、太空与天文；重大事件的三维过程解释。
- **C 事物内部与工作原理**：工业设备、交通工具；建筑、工程与基础设施；科技原理与内部结构。

## 三、三种视觉生产模式（不要所有视频都用 3D）

| 模式 | 引擎 | 适用内容 |
|---|---|---|
| 2D 动态图文 | HyperFrames | 排名、榜单、数据分析 |
| 3D 可视化 | Three.js（Blender 备选） | 地理、空间、结构、模拟 |
| 知识动画 | Manim | 原理、数学、科学解释 |

初期资源分配建议：**70%~80% 常规数据内容继续走 2D**，只有具备空间展示价值的选题进 3D，
特殊科学知识内容才调 Manim。（这是建议比例，不是已验证的最优比例。）

### Blender 与 HyperFrames 的分工

**不让 Blender 承担整条视频的制作。** 60 秒样例结构：

| 时间 | 承担者 | 作用 |
|---|---|---|
| 0–5s | Blender / Three.js | 三维地球、镜头推进，制造视觉钩子 |
| 5–15s | HyperFrames | 区域高亮、航线、动态标注 |
| 15–45s | HyperFrames | 排行榜、数据图表、事件分析、文字动画 |
| 45–60s | Blender + HyperFrames | 三维收尾、结论、关注引导 |

三维场景做成**可复用模板**，只替换国家、数字、路线和镜头参数，不每条从零建模。
简单三维地图与数据动画，Three.js 就能承担。

## 四、架构上只加两样东西

不给 3D 另造一套内容流水线，而是在现有流程里加**统一的视觉模式选择**：

```
AI 内容分析与选题策划（趋势/数据/选题评分）
        ↓
AI 视频策划 Agent（内容结构、分镜、镜头、视觉模式）
        ↓
2D HyperFrames │ 3D Three.js │ 知识动画 Manim   ← 按选题选，可混合
        ↓
统一后期：FFmpeg · 配音 · 字幕 · 音乐 · 编码
        ↓
审核、存储、发布
```

第二个东西：**让 AI 输出结构化的 VideoSceneSpec，而不是让模型自由编写 Blender/Three.js 代码。**

```json
{
  "visualMode": "3d",
  "sceneType": "global_trade_routes",
  "duration": 60,
  "scenes": [
    { "type": "earth_intro",      "duration": 5,  "camera": "global_zoom_in" },
    { "type": "shipping_routes",  "duration": 20, "dataSource": "trade_route_dataset", "animation": "route_flow" },
    { "type": "data_comparison",  "duration": 25, "visualMode": "2d" }
  ]
}
```

分工：**AI 负责创意与数据解释，渲染引擎负责稳定执行。** 好处是以后能无痛替换/增加渲染后端。

## 五、分期路线

| 阶段 | 建设内容 | 优先级 |
|---|---|---|
| 一 | 建立 2D / 3D / 知识动画模式选择 | P1 |
| 二 | Three.js 地球、地图、路线模板 | P1 |
| 三 | 3D 数据场景与资产库 | P1 |
| 四 | Blender 高质量特殊场景 | P2 |
| 五 | 依视频数据反哺 3D 选题与视觉优化 | P2 |

**首期技术栈**：Three.js（主三维渲染）+ HyperFrames（整体编排）+ GSAP（动画控制）+ FFmpeg（合成）。
Blender 暂只作未来特殊三维资产制作工具。

## 六、首批模板与验证实验

### 三个可复用模板

1. **全球地球与航线**——地理、贸易、能源
2. **三维地形与地图**——城市、区域、资源
3. **三维结构剖面**——建筑、交通、工业
4. （备选）**三维数据网络**——经济、产业链、物流

### 三个实验视频

| # | 标题 | 视觉重点 |
|---|---|---|
| 1 | 全球最重要的 5 条航运路线，一旦中断会发生什么？ | 地球旋转、海峡高亮、船舶航线、国家贸易数据 |
| 2 | 如果一颗小行星撞击地球，会发生什么？ | 太空视角、撞击过程、影响范围、科学数据 |
| 3 | 一座现代城市的地下，究竟藏着多少东西？ | 城市剖面、地铁、管网、地下交通与基础设施 |

### 验收指标（6~10 条对照普通 2D 视频）

3 秒留存、平均播放时长、完播率、分享率、单条生产成本。**没有明显收益就不扩大投入。**

## 七、风险与边界

- **成本与算力**：复杂 Blender 渲染不放生产服务器批量执行。先用少量预制场景验证，
  再决定是否新增独立渲染节点。
- **科学真实性**：形式 1/2 的"极端假设"最容易出传播，也最容易出错。结论必须能溯源到数据或权威口径，
  推演部分要和事实分开标注。
- **历史还原**：区分考古证据、史料与艺术推演（见形式 4 红线）。
- **传播数字不可当指标**：本文所有播放/粉丝数字均为第三方转述，未核验，不可作为立项依据的唯一支撑。
- **不要把 3D 做成默认**：3D 一旦变成默认表达，成本和出错面都会失控；它只服务"有空间关系的选题"。

## 八、与 Heron 现有术语的映射（避免混淆）

- 3D 不该新增一条 `ProductionBizType`，而应作为**数据看板线内部的一种视觉表达模式**（`visualMode` 层）。
- 栏目（全球数据图鉴、科技竞争力、商业观察室、全球市场、趋势解码）是数据看板线内部的选题分类，
  与"视觉模式"不是一个层级，不要并列。
- 文稿解说线（`kind=article`）与数据看板线（`kind=data_board`）的区别是画面由什么驱动，
  3D 改变的是后者的画面呈现方式，不改变 `kind` 的语义。

## 最终定位

Heron 不应该只是"把数据变成视频"，而要逐步具备**把数据变成故事**的能力：

- 二维图表负责把数据**说清楚**；
- 三维场景负责把复杂的**空间关系**展示出来；
- AI 负责找到**值得讲述的故事**。
