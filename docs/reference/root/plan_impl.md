## 三、Heron 当前业务方向

请严格理解 Heron 的产品定位。

Heron 是一个自动化短视频内容生产平台。

目前主要有两条内容生产线：

**第一条：数据看板内容线（主要业务）**

通过数据看板、趋势、指标变化、异常检测和数据分析发现值得制作的视频主题。

这条线应该是主要的视频内容来源。

要求视频不能只是机械地展示数据和念数字，而要将数据转化为普通观众感兴趣的故事。

例如：

- 一个数据突然发生变化，背后意味着什么？
- 为什么某个行业正在发生变化？
- 哪些数据反映了一个容易被忽视的趋势？
- 数据之间有什么反差？
- 这个变化会影响哪些普通人？
- 一组数字可以讲出什么有意思的故事？

**第二条：新闻内容线（辅助业务）**

新闻线主要负责发现有传播价值的热点事件。

不是所有新闻都要自动发布，应该更加注重新闻的传播价值、事实核验和内容质量。

视觉风格上可以使用专业新闻媒体包装。

不要把 Heron 改造成一个单纯的新闻视频生成器。

## 四、建立三套原创视频视觉风格

这是本次升级最重要的交付物之一。

不要让每个视频都使用同一种模板，也不要让每个视频随机使用不同模板。

需要建立一套统一的设计规范，并根据内容类型选择合适风格。

### 风格 A：Professional News

专业新闻媒体风格。

适用场景：热点新闻、重要事件、权威信息解读。

设计特点：

- 专业媒体包装。
- 清晰的标题层级。
- 新闻播报式信息结构。
- 专业的下三分之一信息条（Lower Third）。
- 数据和来源展示。
- 地图与事件时间线。
- 具有识别度的片头和片尾。
- 克制、专业的动效。

不要做成廉价的 PPT 新闻。

### 风格 B：Data Investigation

数据调查纪录片风格。

适用场景：数据异常、产业变化、市场趋势、深度分析。

设计特点：

- 电影纪录片式构图。
- 富有层次的背景和视觉纹理。
- 数据对比和关键数字强调。
- 趋势变化动画。
- 时间轴和事件关系图。
- 多场景叙事。
- 有节奏的镜头推进和画面切换。
- 关键结论的视觉强化。

这套风格应该成为 Heron 数据内容线的重要视觉风格。

### 风格 C：Dynamic Data Explainer

动态数据解释型视频。

适用场景：数据看板解读、指标变化、排行榜、趋势分析、数据科普。

设计特点：

- 动态柱状图、折线图、饼图。
- 数字滚动和增减动画。
- 数据排名动态变化。
- 地图区域高亮。
- 指标对比和变化过程。
- 重点结论的逐步呈现。
- 字幕与画面紧密配合。
- 丰富但不过度花哨的动效。

这套风格应该突出数据的可读性和信息传达效率。

### 风格系统要求

每套风格都必须有自己的：

- 色彩 Token。
- 字体 Token。
- 字号规范。
- 布局规范。
- 动效规范。
- 转场规范。
- 组件选择规范。
- 场景组合规范。
- 背景设计规范。

风格必须可配置、可扩展，而不是将颜色、字体和动画参数散落在代码各处。

中文字体必须重点考虑，防止中文字体缺失、乱码、溢出、字重不一致等问题。

## 六、升级视频叙事和场景编排能力

特别注意：观众是否愿意继续观看，不仅取决于动画是否漂亮，还取决于视频讲得是否有意思。

请检查现有脚本生成、场景规划和视频生产流程。

在不破坏现有业务接口的前提下，评估并实现以下能力：

### 1. 开场 Hook

视频开始的 1～3 秒需要明确吸引观众。

例如：

- 令人意外的数据。
- 强烈的反差。
- 一个值得追问的问题。
- 一个重要结论。
- 一个具有冲击力的趋势。

不要每条视频都使用相同的开场话术。

### 2. 场景规划

将视频脚本转化为场景序列。

每个场景需要尽可能明确：

- 场景目的。
- 旁白内容。
- 屏幕文字。
- 需要展示的数据。
- 使用的组件。
- 视觉风格。
- 动画效果。
- 时长。
- 与前后场景的衔接。

不能简单地将一段旁白拆成几个文本框。

### 3. 叙事节奏

检查是否存在：

- 长时间静态画面。
- 大量重复动画。
- 连续展示无关数据。
- 旁白与画面不匹配。
- 同一镜头停留过久。
- 画面信息过载。
- 场景之间缺少逻辑关系。

根据内容复杂度动态控制场景长度和信息密度。

### 4. 视觉表达优先

重要信息要通过动画、图表、对比、变化过程呈现。

不能所有信息都依赖字幕和旁白。

尤其是数据类视频，应当让观众一眼看出变化、对比和结论。

## 七、增加视频质量检查闭环

请建立真正能够检查视频质量的机制。

不允许仅仅通过 FFmpeg 能否生成 MP4 来判断视频合格。

至少考虑以下维度：

| 检查维度 | 检查内容 |
|---|---|
| 技术质量 | 视频能否正常播放、音视频时长、分辨率、帧率 |
| 画面质量 | 黑屏、空白帧、异常画面、图层重叠 |
| 文字质量 | 字体缺失、乱码、超出画面、字幕遮挡 |
| 动效质量 | 动画是否正常、是否存在突兀跳变 |
| 节奏质量 | 静态镜头过长、场景切换过于频繁 |
| 叙事质量 | 场景是否围绕主题、逻辑是否连续 |
| 信息质量 | 关键数据是否清晰、来源是否明确 |
| 内容吸引力 | 开场是否有吸引力、是否存在反差和故事性 |

要求：

1. 建立关键时间点截图机制。
2. 可以生成视频的关键帧预览图或 Storyboard。
3. 对截图进行人工可检查的质量验证。
4. 优先使用现有工具和依赖完成质量检查。
5. 自动检查可以明确判断的问题。
6. 主观的美观程度不能伪装成客观的自动评分。
7. 对无法自动可靠判断的项目保留人工审核入口。

如果现有架构允许，可以为每次视频生成记录质量检查结果，方便后续分析。

## 十一、最终验收标准

本次任务不能以新增代码数量作为完成标准。

请重点验证以下结果：

- 三套风格是否真正存在视觉差异。
- 视频是否比原来更有层次感。
- 是否减少了大量静态文字展示。
- 数据是否能通过动画表达变化和反差。
- 开场是否更有吸引力。
- 场景之间是否衔接自然。
- 中文字幕和排版是否稳定。
- 是否可以快速复用已经制作好的视觉组件。
- 后续新增视频风格是否方便。
- 自动生成的视频是否更接近专业短视频作品。

**最重要的一点：不要把 Heron 做成一个技术上很复杂、但产出的视频依然像 PPT 的系统。**

我真正需要的是：输入一个有价值的数据主题，Heron 能够分析出值得讲述的故事，生成有吸引力的脚本，合理安排场景，使用专业视觉组件和动效，最终产出一条画面丰富、节奏自然、信息清晰、值得观众看下去的视频。

请以实际成片质量作为最终目标，而不是以完成了多少技术改造作为目标。
