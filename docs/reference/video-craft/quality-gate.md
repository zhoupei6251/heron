# 出片前检查

把前五篇的要点压成一张可执行清单。分两类：**机器能查的**，和**只能人眼看的**。

## 机器能查的

`hyperframes check` 已经把技术契约检查做完了（见 [../hyperframes/lint-rules.md](../hyperframes/lint-rules.md)）。这些不要重造轮子：

- 对比度（WCAG AA）
- 字体是否声明了 `@font-face`（`font_family_without_font_face`）
- 定时属性、变量绑定、确定性约束
- 素材引用是否存在

## 只能人眼看的

技术检查全绿，片子依然可能没人看完。下面这些是 `check` 查不到的。

### 前三秒

- [ ] 第一拍用结果语言说清了「为什么要看下去」
- [ ] 钩子里没有数据集名、字段名、栏目名这类内部词汇
- [ ] 钩子里的数字带赌注，不是清单

### 叙事

- [ ] 价值主张在第二拍前落地
- [ ] 删掉所有证据拍，剩下的仍能独立说清价值
- [ ] 每帧的「为什么」都能追溯到价值主张；追溯不到的帧被砍掉了，而不是被装饰了
- [ ] 视觉道具都能追溯到材料本身，换成别的产品就不成立

### 画面

- [ ] 每个场景有背景/中景/前景三层，入场期间画面不是空的
- [ ] 每个装饰元素都有环境动效（呼吸/漂移/脉冲），没有死的装饰
- [ ] 每个场景至少有一个颜色拽住眼睛，强调色看得见（不是 5% 光晕）
- [ ] 至少两个焦点，内容锚定到边缘，不是居中悬浮
- [ ] 入场用了 3 种以上不同的缓动和方向
- [ ] 没有全屏线性渐变压在暗底上

### 尺寸

- [ ] 没有低于 24px 的字号（竖屏信息流是 32px 起）
- [ ] 装饰透明度没有低于 10%
- [ ] 主标题占画面宽度 60–80%

### 数据

- [ ] 没有饼图、多轴图、六宫格、网格线、图例
- [ ] 图表是 GSAP + SVG/CSS 手搭的，不是图表库输出
- [ ] 每个数字都配了给重量的视觉元素，没有孤零零飘着的数
- [ ] 同一概念的连续指标保持同一视觉空间，只有数值在变
- [ ] 数字容器固定宽度 + `tabular-nums`，9→10→100 不抖
- [ ] 条形用 `scaleY/scaleX` 缩放，没有 tween `height/width`
- [ ] 进度条 `.fill` 有 `width: 100%`
- [ ] 数字和配图同起点、同缓动、同时落定

### 节奏

- [ ] 节奏型是先命名再实现的（`快-快-慢-SHADER-停`）
- [ ] 能量峰落在旁白最重的那句上
- [ ] 关键画面停留 ≥3 秒（= 2 秒读完）
- [ ] 转场数量克制：5–7 拍的片子不超过 1–2 个 Shader

### 字幕

- [ ] 竖屏字幕距底 600–700px，不是贴底
- [ ] 同一时刻只有一组字幕
- [ ] 强调词有比周围更重的处理
- [ ] 用 `fitTextFontSize` 量过，没有溢出

### 一致性

- [ ] 有 `frame.md` 的话，色值和字族与它一致
- [ ] 全片一个主色，背景色不跨场景乱换
- [ ] 没有触发 [frame-design.md](frame-design.md) 的 AI 套路清单（除非是有意识的选择）

### 可信度

- [ ] 口播里的数字和画面上的数字一致（「接近三成」vs `31.7%` 是可信度杀手）
- [ ] 数据来源在片中出现或可追溯

## 结论

这些清单解决的是「看起来像做的」，不解决「有人看」。

留存最终由钩子、冲突、信息密度、节奏和发布后的数据反馈决定——前五项在这里，最后一项在 Heron 的数据回流里。

**这条片子的完播率、前三秒留存，比这张清单的任何一项都更能说明问题。**
