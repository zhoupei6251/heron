# 数据新闻编辑引擎设计

**版本**：2026-11-11 · v2（两线并行 + 分层决策）
**适用范围**：新闻视频生产线的两条子线 —— 数据看板线（`DATA_BOARD`）与新闻解说线（`NEWS_EXPLAINER`）
**取代关系**：v1 只规划数据看板单线；v2 改为两线并行，由模型决定当天走哪条，解说线保持低权重

---

## 0. 定位

不做「按固定栏目、固定图表生产视频」的系统，做**由模型分层决策、由代码划定边界**的编辑引擎。

**模型负责编辑判断与创作，Java 负责客观验证与执行约束。** 两侧互不越界：
- Java 不判断哪条新闻值得发布。
- 模型不重新计算数据，也不验证事实真伪。

判据是观众看完，不是「把数据画出来」。

---

## 1. 两条线并行

| | 数据看板线 | 新闻解说线 |
|---|---|---|
| `kind` | `data_board` | `article` |
| 模板前缀 | `news-data-*` | `news-*`（12 套） |
| 输入 | 热榜标题 + 数据集 | RSS 正文 + 事件 |
| 画面主体 | 图表 | 文字排版 |
| 权重 | 高（默认方向） | 低（要有明显爆款相的题材才走） |

**权重由提示词表达，不设硬配额。** 但有一条代码级边界：解说线需要正文，而热榜候选没有正文（`parseWeibo`/`parseBaidu` 的 `summary` 存的是来源名）。所以候选池必须按素材能力分开：

- **解说候选池**：只有 RSS 源（IT之家、少数派、爱范儿、钛媒体、199IT），带完整正文
- **看板候选池**：全部热榜候选 + 数据集检索结果

模型不能凭标题判定「这条能爆」而选解说线，那会拿到空正文。这是边界，不是权重。

## 2. 分层决策：正常 5 次调用

| # | 角色 | 只做一件事 | 输入 |
|---|---|---|---|
| LLM-1 | 总编辑 `DAILY_EDITOR` | 走哪条线，或 `NO_PUBLISH` | 热榜摘要、两线候选概况、最近 7–30 天发布记录、编辑策略提示词 |
| LLM-2 | 线内编辑 `DATA_BOARD_EDITOR` / `NEWS_EDITOR` | 选数据集+形态 / 选文章+角度 | 该线的合法候选详情 |
| LLM-3 | 标题 `TITLE` | 出多个候选标题 | 已选素材 + 事实清单 |
| LLM-4 | 正文 `SCRIPT` | 写稿 | 素材 + 事实清单 + 选中的标题 |
| LLM-5 | 审稿 `REVIEWER` | 审表达，不验事实 | 成稿 + 已验证事实清单 |

**修复是条件调用**：审稿返回 BLOCKER/MAJOR 时 +1，修复后必经 Java 硬闸再复审，不过就放弃，不无限重试。

**跨线回退**：总编辑选了数据看板但线内编辑发现没有合适数据集时，**回退到另一条线再调一次线内编辑**（+1），而不是直接放弃或回问总编辑。一个日更账号直接弃更的代价太高。

最坏情况 8 次（含回退与修复），正常 5 次。

**标题为什么单独一次**：实测让同一模型在写稿时顺手起标题，产出的标题不可用。拆成独立调用后产出五个候选、覆盖五种钩子（数字反差/疑问悬念/利益相关/时间紧迫/反常识），再由写稿环节原样挑选一个。

**没有「视频导演」这一层**：这个系统里分镜就是模板本身，GSAP 时间轴写死入场、推进、定格、退场。模型只能决定文字槽位和图表类型，拿不到动画控制权。多设一层「导演」没有可导的东西。

## 3. 审稿人的边界

**核心原则：审文案有没有正确表达已验证的事实，不重新验证事实。**

| 审查项 | 负责 | 说明 |
|---|---|---|
| 标题是否夸大、制造虚假冲突 | 是 | |
| 逻辑是否跳跃 | 是 | 结论能否从前文推出 |
| 是否误用数字、涨跌说反 | 是 | 对照 Java 给的事实清单 |
| 信息密度、口播节奏 | 是 | |
| 数据是否真实、计算是否正确 | **否** | `DatasetFacts` 按快照重算，`data_sha256` 绑定 |
| 来源是否有效、占位符能否解析 | **否** | `DatasetContract` / `DatasetScriptContract` 已验 |

**两线的事实清单不是同一种东西**，必须分开命名，否则会把未经验证的说法当成已验证事实：

- 数据看板线：`validatedFacts` —— 来自快照 `facts` 节点，Java 已用同一口径重算比对
- 新闻解说线：`quotes` —— 每条带「原文片段 + 来源 URL + 抓取时间」，审稿规则是「文案是否超出原文说过的范围」，**不是**「事实是否成立」

**`factRefs` 不用改契约**：正文用 `{{facts.<路径>}}` 占位符，每段引用了哪些事实，`DatasetPlaceholders` 解析时即可得到，由 Java 提取后随审稿输入给出。

**审稿分级处置**：

| 级别 | 例子 | 处置 |
|---|---|---|
| BLOCKER | 涨跌说反、标题误导、「全球第一」但只覆盖 10 国 | 必修 |
| MAJOR | 逻辑跳跃、关键背景缺失、口径易误解 | 必修 |
| MINOR | 措辞不漂亮、句子不够顺 | 只记录 |

没有分级，审稿模型会因为审美偏好无限要求重写。

## 4. 三个注册中心

| 中心 | 权威来源 | 现状 | 待补 |
|---|---|---|---|
| 数据集中心 | MySQL `heron_data_source` | 119 条，108 条启用且探测正常 | 提供方与数据集拆开 |
| 视觉模板中心 | **文件**（模板目录的 `template.json`） | 仅有名字与一句话描述 | 声明形态、时长、节奏档、必需字段、示例数据 |
| 编辑记忆 | MySQL | 仅 `heron_dataset_usage` 7 天源级去重 | 选题级判重、模板与线使用记录 |

**模板为什么用文件权威**：`LOCK.json` 与 `assets-manifest.json` 已对模板文件算过哈希，数据库再存一份元数据只会过期。模板是代码资产，改动本来就要走 git、跑 `hyperframes check`、重算哈希。

**形态由适配器声明**：`DatasetAdapter.shape()`，抓取后比对快照实际 `shape`，不一致按闸拒绝。注册表 `shapes` 列降级为展示。

## 5. 数据形态决定形态数量

| 形态 | 有适配器产出 | 有模板渲染 | 契约声明 |
|---|---|---|---|
| `wide` | 是 | 折线 | `line` |
| `rows` | 是 | 排行 | `bars` |
| `long` | OWID 人口 / 碳排放赛跑 | 赛跑 | `race` |
| `geo` | **零** | **零** | `map`（空声明） |

**形态数量由数据形态决定，不是随便加画法。** 气泡图（x/y/尺寸/时间）、热力图（行列网格）、事件时间轴都需要新的 `shape`，每加一个要动契约、闸、适配器、模板四处。

**第一批**：折线 / 排行（已有）+ 赛跑（已有）+ 堆叠面积 / 多线叠加 / 雷达（共用 `long`，待做）。**地图第二批**：同时缺地理数据源、geojson 资产和竖屏排版方案，与其余形态零复用。

**竖屏行数由数据决定**：`显示行数 = min(实体数, 14)`，上限由 24px 最小可读字号反推（900px 可用高度）。超出部分进榜时从底部滑入。

## 6. 候选准备（Java，无模型）

热榜与 RSS 并行采集 → 事件聚类去重 → 数据集检索（关键词重合度）→ 实际探测 → 合法（数据集, 模板）组合。

检索召回上限 60，按重合度排序后取前 12–15 交给线内编辑。接口留了两条候选池，两条线不必都走完整生产。

## 7. 判重与编辑记忆

源级去重不够：同一事件换数据集拦不住，同一数据集换角度却被误拦。

**关键词判重**：模型在决策时输出一组关键词，代码按下式比对历史发布记录：

```
分词：英文与数字按词切并转小写，中文按单字切
重合度 = |A∩B| / |A∪B|   （Jaccard）
阈值 0.5 起步
```

判重与判不重都记录计算结果，供事后调阈值。

`shortcut:` 单字切分认不出同义改写（「算力」与「芯片」重合度为 0），初期靠模型看发布历史补语义；误判率超过两成才上同义词表。

## 8. 节奏与音频

**语速实测 4.62 字/秒**（166 字 ÷ 35.9 秒）。节奏是模板属性，由 `template.json` 声明：

| 档 | 每拍 | 正文长度 | 适用 |
|---|---|---|---|
| 快 | 4–5 秒 | 18–24 字 | 赛跑、逐位揭晓 |
| 中 | 6–7 秒 | 28–35 字 | 多线叠加、对比 |
| 慢 | 8–10 秒 | 40–70 字 | 收尾结论 |

**已知缺陷**：`index.motion.json` 的 `keepsMoving` 断言检查 `#root`，而进度条一直在动，所以永远通过——自动检查检测不到「图表静止」。要修它必须先把折线模块改成持续有动作，否则改断言会让现有模板判失败。

**音频**：19 个音效与 6 首 BGM 已入库（`data/audio/`）。音效按模板时间轴静态摆放，不需要事件驱动系统。

## 9. 扩展性

新增一条线（财经、科技专题、国际事件）只需三样：新的候选池、该线的编辑提示词、生产适配器，然后把新线加入总编辑的合法选项。不需要重写系统。

---

## 10. 落地顺序

1. 恢复解说线：解开 `article-enabled`，先跑通一次真渲染（已停用一段时间，回归未验证）
2. 总编辑决策：候选池准备 + `DAILY_EDITOR` 提示词 + `NO_PUBLISH` + 跨线回退
3. 线内编辑合并形态与模板选择：模型一次选定（数据集, 模板），代码只给已验证兼容的组合
4. 标题 / 正文 / 审稿三段的提示词落库到 `resources/heron/`
5. 堆叠面积 / 多线叠加 / 雷达（共用 `long`）
6. 第二批：地图
