# heron 原型工坊需求文档（2026-10-28）

> 结论先行：把附件那份「AI 一键生成 Axure 原型 SaaS」PRD 蒸馏进 heron，做成**第二条业务线**——
> 需求 → RP/1 源码 → 原生 `.rp`。留下的是它的验收纪律（引擎版本钉住、DSL 快照、授权下载、
> 失败原因分类、四类证据分开统计）；删掉的是 heron 已经有的（租户/RLS/审计/用量）和明确不做的
> （自助注册、套餐计费、MinIO、pg-boss、自研第二个渲染器）。
>
> 与新闻线的边界：**共用**租户、身份、RLS、模型客户端、审计、用量记账；**不共用**任务表、状态机与页面。

## 1. 与附件 PRD 的差异（蒸馏结果）

| 附件 PRD | heron 处置 | 理由 |
| --- | --- | --- |
| 用户注册 / 套餐 / 定价 / 企业私有化 | **不做** | heron 是自部署，超管建空间与账号；无自助注册路径，也无支付 |
| MinIO 对象存储 | **改用**现有本地盘 `data/` | 开源目标：默认零额外中间件；下载走鉴权接口，不给公开 URL |
| pg-boss / Prisma | **改用**现有 BullMQ（可选）+ Drizzle | 已落地，不换 |
| 4.8「HTML 预览由 DSL 渲染」 | **改用**引擎自带的离线 `compile` 预览图与审计报告 | 自研第二个渲染器 = 第二套真相；预览图是审片证据，不承诺与原生运行一致 |
| 4.5 页面规划人工确认（多一步） | **砍** | 多一次人工往返，价值不如 review 闸；规划结果随版本快照一并留痕 |
| 需求文档上传 / 截图重建 | **砍** | 截图 OCR 依赖 macOS Vision，本机与镜像都跑不了；文件解析另立 |
| 局部修改、版本间合并 | **砍** | PRD 自己也写「首版允许整版重新生成」；重跑 = 新版本，旧版本不删 |
| 4.9 九态任务 | **收窄为** 7 态（见 P3） | `retrying`/`cancelled` 没有对应的真实动作，先不加 |
| 版本管理、引擎版本、DSL 快照、幂等创建、授权下载、失败分类 | **照收** | 这些正是 heron 已有闸门纪律的同构要求 |

## 2. 前置事实（2026-10-28 在本机实测）

1. `zee-rp`（MIT，当前 CLI 路径无需 npm 依赖）的 `check` 与 `generate --compile-only` **不需要 Axure**：
   前者出 `structural_ok` 与诊断，后者出多页预览图（`pages-sheet.png`、`@2x`）与两级审计报告。
2. 基础控件装配原生 `.rp` 需要 Axure 另存的 RP9 单页空白工程，路径由
   `AXURE_BLANK_TEMPLATE_RP9` 指定。后续容器核验确认：动态面板另需 `RP9 Tour.rp`，原生输入框和 Repeater 另需 `Default.rplib`，不能再笼统称为“只缺一个文件”。默认模型提示词仅用基础控件与页面跳转，不冒充已验证高级控件。
3. 因此**服务器上不需要装 Axure 运行**；但「生成的文件在 Axure 里能打开」这件事只能由人证，
   系统不得伪造该结论。
4. 未验证：Windows/Linux 上装配出的 `.rp` 能否被 Axure 打开、交互是否符合预期。这是阶段 A 的全部内容。

## 3. 需求条目

### P1 项目与版本

- 原型项目：`title`、`requirement`（需求原文）、`target`（`web`/`mobile`）、`theme`、`stage`、
  `error_reason`、租约三件、`created_by`、创建/更新时间，带 `tenant_id` 走 RLS。
- 每次生成一个版本，存 `rp1_source`（模型原稿）、`engine_version`（引擎 tag）、`audit`（审计原文）、
  预览图路径、`.rp` 路径与 sha256、模型名与 token 数、失败原因。旧版本不删。
- **验收**：同一项目连续生成两次 → 两条版本、两份预览，互不覆盖；已交付版本不会因新任务被改写。

### P2 需求输入与校验

- 输入：项目名 + 需求描述（上限 8000 字，空则拒绝）+ 画布（Web 管理后台 / 移动端）+ 风格主题。
- **验收**：空需求、超长需求在接口层拒绝并给出字段级原因；前端的字数上限与后端一致（同一常量）。

### P3 生成流水

```
draft → scripting → compiling → review → approved → delivered
                          ↘ failed（带 error_reason）
```

- `scripting`：调现有 model client 写 RP/1。提示词含 RP/1 速查（页面/容器/组件/变量/跳转的合法写法）。
- `compiling`：`check` → `compile` → 装配 `.rp`。任一步非零退出即 failed，并把引擎 stderr 原文进 `error_reason`。
- 租约与重跑沿用现有 worker 模式：同一项目同时只允许一条在途；租约过期可被重新领取。
- **验收**：模型故意写错一个组件类型 → `failed` 且原因指向 `check` 的那条诊断；修复后重跑生成新版本，旧版本仍在。

### P4 四道闸（按证据分级）

| 闸 | 判据 | 不通过时 |
| --- | --- | --- |
| 契约 | `check` 的 `structural_ok` | failed，附诊断原文 |
| 视觉 | 审计报告四项（色彩收敛/字体合规/语义命名/分组覆盖）全 pass | failed，附未过项与比例 |
| 原生 | 人在 Axure 中打开过 | **不阻断交付，但必须留痕**：确认框勾选项记入版本 |
| 人工 | 确认人 + 时间 + 预览图 sha256 | 未确认不能交付 |

- **验收**：不勾「已在 Axure 打开过」也能交付，但详情页与下载记录上永久显示「未在 Axure 验证」；
  勾了就必须记下是谁、何时勾的。

### P5 产物与下载

- 产物：`.rp`、RP/1 源码、预览图、审计报告。落 `data/protos/<project-id>/v<version>/`。
- 下载必须过鉴权：按项目查租户归属，逐文件授权；响应带 sha256，供人核对拿到的就是审过的那份。
- 单文件上限（默认 50 MB）；`.rp` 为空或 sha256 对不上时拒绝交付并报原因。
- **验收**：换一个项目的 id 下载 → 404（不是 403 也不是 200）；拿另一个租户的会话下载 → 同样 404，
  且 RLS 在库层就查不到那一行，不是靠接口里 if 判断兜住。

### P6 幂等与并发

- 创建生成请求带幂等键，重复提交不产生第二条版本、不重复记账。
- 每租户并发生成数上限（默认 3，环境变量可调），超出直接拒绝并说明当前占用。
- **验收**：双击「开始生成」只出一条在途；并发提交第 4 条被拒且提示是哪个限制。

### P7 用量

- 模型 token 计入现有 `llm_tokens_in` / `llm_tokens_out`，`detail` 里带项目与版本 id。
- 配额拦截属于新闻线 R7，本轮**只记账不拦截**，并在界面注明「当前不计费」。
- **验收**：一次成功生成后用量页出现对应 token 行；失败任务也记录已消耗的 token。

### P8 失败与重试

- 失败原因分四类并明确标注：`contract`（结构校验未过）、`visual`（审美四项未过）、
  `engine`（引擎/依赖缺失，如缺模板）、`model`（模型超时/限流/空输出）。
- 契约与模型类失败**不自动重试**（与新闻线「不自动改稿」同一条理由），由人点重跑。
- 重跑永不覆盖已交付版本。
- **验收**：缺 `AXURE_BLANK_TEMPLATE_RP9` → failed，原因里同时给出变量名与「怎么得到这个文件」；
  预览图仍保留在项目下供诊断。

### P9 平台视角

- 健康探针多两项：引擎目录存在且版本可读、空白模板存在。缺任一项在平台台标红并给出修复指引。
- 不做「在线配置引擎」界面：路径与版本走部署环境，改它 = 换镜像或改变量。

### P10 部署

- 镜像需 Python 3.10+、Pillow 与中文字体（Alpine 的 `python3 py3-pillow font-noto-cjk` 已通过 check/compile 实测）；numpy/scipy/jsonschema 不属于当前 CLI 路径的运行依赖。引擎固定 `v0.2.1`，同时核对 commit `74f286fead2e2524fb5f710b36e2e1db9e861df5`，不跟 `main`。
- 模板不进仓库、不进镜像（Axure 的商业产物），由部署者自备并以只读卷挂载。
- `compose` 增加 `ZEE_RP_HOME`、`AXURE_BLANK_TEMPLATE_RP9`、模板卷；缺模板时**不拒绝启动**，
  但原型线的生成按钮置灰并写明原因（新闻线不受影响）。
- **验收**：`docker compose config` 无默认口令；起容器后健康探针如实报告引擎与模板状态。

## 4. 里程碑

| 阶段 | 内容 | 出口判据 |
| --- | --- | --- |
| A 引擎 PoC | 拿到一份 RP9 空白模板 → 生成一份真实需求的多页 `.rp` | **人在 Axure 里打开、编辑、保存、重开**；失败则不改路线图，先解决引擎 |
| B 引擎接缝 | 子进程封装：超时、退出码、stderr 透传、产物路径规约 | 单测覆盖「引擎非零退出」「超时」「产物缺失」三种失败 |
| C 工坊 MVP | P1–P8 全线 + 独立页面 + 平台探针 | 一个租户从录需求到下载 `.rp` 走完，四道闸可见 |

## 5. 这次不扩的东西

- 移动端 App 原型（引擎支持，但不在本轮验收范围）。
- 截图/参考图重建、需求文档解析、Figma/Sketch 互转。
- 在线编辑 RP/1、版本间差异合并、回写已有 `.rp`。
- 配额拦截与计费、套餐、限流策略。
- 第二个原型引擎适配器（只留一个接口位，不写抽象层）。

## 6. 风险

| 风险 | 应对 |
| --- | --- |
| `.rp` 在本机/镜像装配出来打不开 | 阶段 A 的原生验收仍是发布前置；按用户继续实现的授权，B/C 的代码和演示先行，不等同于 A 或 C 已验收 |
| 模板是商业软件产物，不能随仓库分发 | README 写清获取方式；缺模板的表现可诊断，不是黑屏 |
| 引擎单人维护、star 少、迭代快 | 钉 tag；适配层只有子进程一处；升级 = 换 tag + 跑回归样本 |
| musllinux 轮子缺包（Alpine 基础镜像） | PoC 时验证；不行换 debian slim 基础镜像（代价 +80MB 左右） |
| 模型对 RP/1 不熟，一次生成合格率低 | 提示词附速查 + `check` 诊断回显给人看；不静默重试，人决定重跑 |
| 交互覆盖率无法承诺 | 交付页明写「本版本交互范围」，以审计报告与人在 Axure 的实测为准 |
