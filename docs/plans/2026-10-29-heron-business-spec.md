# heron 业务文档

**版本**：2026-10-29 · v1（待评审）
**适用基座**：RuoYi-Vue-Plus 6.0.0（Spring Boot 4.1.2 / JDK 21 / MyBatis-Plus / Sa-Token）+ plus-ui（Vue 3 + Element Plus）
**产品形态**：单租户、自部署
**取代关系**：取代 heron-temp 中基于 NestJS + Postgres + 多租户的旧规格；旧文档降为业务规则 oracle，不再作为技术实现依据。

---

## 0. 本次变更

| # | 变化 | 影响 |
|---|---|---|
| 1 | 技术基座：NestJS / TypeScript → Java（RuoYi-Vue-Plus 6.0.0）+ Vue3（plus-ui） | 旧代码不迁移，业务在新基座重写 |
| 2 | 产品形态：多租户 SaaS → 单租户自部署 | 租户台、平台台、套餐、配额、计费、RLS 全部移出范围 |
| 3 | 旧实现只作规则 oracle | 状态机、五道闸、确认三样、失败语义、验收口径保留 |

**结论**：这是一次「业务保留、实现重写、租户模型降级」的变更，不是简单换框架。

## 1. 产品定位与边界

**一句话**：一台自己部署的机器上的内容生产工作台——热榜进、成片出、人确认、服务端发布；第二条线把需求变成可下载的 Axure 原型。

**两条业务线**：

1. 新闻视频生产线：热榜采集 → 候选 → 写稿 → 核查 → 渲染 → 审片 → 确认 → 抖音发布。
2. 原型工坊：需求 → RP/1 源码 → 原生 `.rp` 原型 → 审阅 → 下载。

**共同原则**：

- 生产可以自动，**发布/交付必须人确认**。
- 每道闸有真实判定；失败必须给出原因，不允许静默通过。
- 单人/小团队可运维：单机部署，不引入不必要的中间件。

**不做**（写死，防止顺手加回来）：

- 多租户、SaaS 套餐、计费、自助注册、租户台/平台台。
- 无人值守自动直发。
- 微服务拆分、serverless（无 ffmpeg/Chromium）。
- 为第二个内容类型预先做平台抽象。
- 移动端 App、邮件/IM 通知、在线支付。

## 2. 用户与角色

| 角色 | 职责 | 基座映射 |
|---|---|---|
| 系统管理员 | 账号、角色、菜单、参数、日志、存储、任务；全部业务 | RuoYi `admin` + 系统管理菜单 |
| 制作人 | 维护热榜源、看候选、开始生产、改稿、重跑 | 角色 + 业务按钮权限 |
| 审片人 | 审片台确认、原型交付确认、下载 | 角色 + 业务按钮权限 |
| 只读 | 查看列表与进度，不做动作 | 只读角色 |

- 权限模型直接用 RuoYi 的「角色 + 菜单 + 按钮权限」，不自建 RBAC。
- 单租户：**部署边界就是隔离边界**；数据模型不带 `tenant_id`，不实现 RLS。
- 发布账号是机器身份（cookie / 开放平台凭据），不是登录用户；凭据不落业务库。

## 3. 业务线 A：新闻视频生产线

### 3.1 核心对象

| 对象 | 作用 |
|---|---|
| 热榜源 | URL、抓取频率、上次抓取时间、失败原因 |
| 候选 | 标题/摘要/命中词/热度/去重键；认领前只有文本 |
| 任务 | 状态机、租约、重试次数、失败原因 |
| 稿件 | 标题、分镜、屏句；一任务一份，重写覆盖 |
| 成片 | 版本、mp4、联络表、时长、指纹、对象键 |
| 确认 | 确认人、确认时间、联络表指纹 |
| 发布 | 幂等键、回执、状态、失败原因 |
| 用量 | 模型 token、渲染秒数、发布次数 |
| 闸结果 | 哪条闸、输入片段、判定、原因 |

### 3.2 生命周期

```
候选 → 已认领 → 写稿 → 核查 → 渲染 → 审片 → 已确认 → 发布中 → 已发布
                                    ↘ 失败（带原因）
```

- `核查`、`审片` 是闸，不是可选步骤。
- 每次状态迁移落库并带原因；HTTP 请求不等待渲染，进度用 SSE 或轮询。

### 3.3 输入与候选

- 热榜源支持 RSS/Atom/纯文本；定时抓取 + 页面手动触发。
- 抓取失败在源上留下失败原因与下次重试时间，不静默。
- 同一新闻按去重键合并，累加命中次数/热度/最高排名。
- 同一候选同时只允许一条在途任务；认领人来自登录会话，接口不能塞值。
- 手工建任务保留，用于调试；正式入口是候选「开始生产」。

### 3.4 五道闸

| 闸 | 位置 | 拦什么 | 不通过 |
|---|---|---|---|
| 去重 | 候选建立时 | 已发布过的去重键 | 不生成候选 / 不产生任务 |
| 契约 | 核查 → 渲染 | 缺稿、字段形状、标题与屏句重复；版式定稿后加字号/填幅/领句位 | 退回写稿，列出不过的条目 |
| 视觉 | 渲染 → 审片 | 对比度、填幅、占位 | 失败，附未过项与比例 |
| 合规 | 已确认 → 发布 | mp4 `AIGC` 元数据 + 「内容由 AI 生成」声明 + 姿态要求 | 拒绝发布，不可跳过 |
| 人工 | 审片 → 已确认 | 人的确认 | 未确认不能发布 |

- 契约 8 条里与版式相关的几条在版式定稿后补齐；现在不冒充已实现。
- 闸门要能置灰界面：未达条件时「发布」按钮不可点。

### 3.5 人工确认三样

必须同时记录：**确认人、确认时间、当时联络表的版本指纹**。

- 重渲产生新版本/新指纹 → 原确认失效，必须重确认。
- 少第三样就会出现「人审 A、系统发 B」。
- 确认动作是发布唯一入口；不允许接口绕过。

### 3.6 发布

- 人确认后服务端自动执行；发布适配器按平台切。
- 幂等键：`taskId:v版本号`。
- **重试前先查外部真实状态**；回执丢失不等于没发出去，直接重试会发两遍。
- 回执、失败原因、发布账号标识入库。
- 首选抖音开放平台 `video.create`（官方授权链路）；Playwright 网页上传仅作降级，并写明随平台改版即失效、有账号风控风险。
- 未配置凭据 / 未审核通过时，发布按钮置灰并给出原因。

### 3.7 失败语义

| 失败类 | 例子 | 处置 |
|---|---|---|
| 契约 | 缺字段、标题与屏句重复 | 退回写稿，列条目；不自动改稿 |
| 视觉 | 对比度 / 填幅不过 | 失败，附未过项；保留产物 |
| 合规 | 缺 AIGC 标识 | 拒绝发布，不可跳过 |
| 模型 | 超时、限流、空输出 | 失败，原因入库；人决定重跑 |
| 发布 | 回执丢失、平台拒绝 | 先查外部状态，再决定重发或补记录 |

- `error_reason` = **哪条闸 + 输入片段 + 为什么拒**；界面可展开全文。
- 不吞异常、不静默重试、不自动改写稿件。
- 渲染失败保留截图/日志/检查结果供诊断。
- 重启恢复：租约过期任务回到可领取；超过次数标失败，等人处理。

### 3.8 保留与清理

- 按保留天数清理成片目录；失败现场（`.keep`）不参与。
- 数据库记录保留：发布单、确认、审计仍指向它；文件没了但账要在。

### 3.9 闭环验收（端到端六步）

1. 加热榜源 → 下一轮出现候选；
2. 人认领 → 任务自动走到审片；
3. 审片台看到成片与联络表，指纹与版本一致 → 确认；
4. 自动发布 → 发布记录有回执、用量有记录；
5. 抖音侧可见，且视频带 AIGC 标识与声明；
6. 故意让渲染失败一次 → 任务失败，原因指出哪条闸、哪段输入、为什么。

任一步靠占位放行，都不算完成。

## 4. 业务线 B：原型工坊

### 4.1 输入与版本

- 项目：名称、需求原文（上限 8000 字，空则拒绝）、画布（Web / 移动端）、风格主题。
- 每次生成 = 一个新版本；旧版本不删、不覆盖。
- 版本记录：RP/1 源码、引擎版本、审计原文、预览图、`.rp` 路径与 sha256、模型与 token、失败原因。

### 4.2 生成流水（7 态）

```
draft → scripting → compiling → review → approved → delivered
                          ↘ failed（带原因）
```

- `scripting`：模型写 RP/1。
- `compiling`：`check` → `compile` → 装配 `.rp`；任一步非零退出即失败，引擎 stderr 原文进原因。
- 同一项目同时只允许一条在途；租约过期可被重新领取。
- 重跑生成新版本，不覆盖已交付版本。

### 4.3 四道闸

| 闸 | 判据 | 不通过 |
|---|---|---|
| 契约 | `check` 的 `structural_ok` | 失败，附诊断原文 |
| 视觉 | 审计四项（色彩收敛 / 字体合规 / 语义命名 / 分组覆盖）全过 | 失败，附未过项与比例 |
| 原生 | 人在 Axure 中打开过 | **不阻断交付**，但必须留痕；未勾选则永久显示「未在 Axure 验证」 |
| 人工 | 确认人 + 时间 + 预览图 sha256 | 未确认不能交付 |

- 系统不得伪造「已在 Axure 打开」的结论。

### 4.4 产物与下载

- 产物：`.rp`、RP/1 源码、预览图、审计报告；落 `data/protos/<project-id>/v<version>/`。
- 下载必须过鉴权：按项目归属与角色逐文件授权；响应带 sha256。
- 单文件上限默认 50 MB；`.rp` 为空或 sha256 不匹配时拒绝交付并报原因。
- 换项目 id 或越权下载 → 404（不是 403、不是 200）。

### 4.5 幂等与并发

- 创建生成请求带幂等键，重复提交不产生第二条版本、不重复记账。
- 并发生成数上限默认 3，超出拒绝并说明当前占用。

### 4.6 失败分类与重试

| 失败类 | 含义 |
|---|---|
| `contract` | 结构校验未过 |
| `visual` | 审美四项未过 |
| `engine` | 引擎/依赖缺失（如缺模板） |
| `model` | 模型超时 / 限流 / 空输出 |

- 契约与模型类失败不自动重试，由人点重跑。
- 缺模板时失败原因同时给出变量名与获取方式；预览图保留供诊断。

### 4.7 引擎与模板前提

- 引擎 `zee-rp` 固定 `v0.2.1`（同时核对 commit），不跟 `main`。
- 服务器不需要装 Axure；`check` 与 `compile` 离线可跑。
- 装配原生 `.rp` 需要 Axure 另存的 RP9 空白工程；动态面板另需 `RP9 Tour.rp`，输入框 / Repeater 另需 `Default.rplib`。
- 模板是商业软件产物：不进仓库、不进镜像，由部署者自备并以只读卷挂载。
- 缺模板不拒绝启动，但原型线生成按钮置灰并写明原因；新闻线不受影响。
- 镜像需 Python 3.10+、Pillow、中文字体；`zee-rp` 固定 tag。

### 4.8 当前阻塞

- 尚未拿到 Axure RP9 空白模板 → 阶段 A（生成一份可在 Axure 打开的多页 `.rp`）无法开始。
- 原生验收只能由人完成；系统不得写「已验证」。

### 4.9 验收

- 同一项目连续生成两次 → 两条版本、两份预览，互不覆盖。
- 故意写错一个组件类型 → 失败原因指向 `check` 诊断；修复后重跑生成新版本，旧版本仍在。
- 未勾「已在 Axure 打开过」也能交付，但详情页与下载记录永久显示「未在 Axure 验证」。
- 下载越权 → 404。

## 5. 管理台与治理

### 5.1 直接采用基座

| 能力 | 用途 | 说明 |
|---|---|---|
| 用户/角色/菜单/部门/岗位 | 账号与权限 | 直接用 RuoYi，不自建 |
| 字典/参数 | 业务默认值（模型、保留天数等） | `sys_config` 平台级；租户级配置随多租户一起砍掉 |
| 公告 | 可选 | 需要才开 |
| 操作日志/登录日志 | 审计 | 与业务留痕互补 |
| 在线用户 | 会话管理/强退 | 替代旧 `sessions` 表 |
| 缓存监控 | 运维 | 直接用 |
| OSS | 对象存储（S3 协议） | 默认本地盘；需要远端再配 S3 兼容存储 |
| 定时任务 | 抓取/清理 | 默认 Spring `@Scheduled`；SnailJob 可选，需额外服务 |
| 代码生成 | 开发工具 | 只用于开发，不进业务 |
| 工作流 | 不用 | 与产品无关 |
| SnailAI | 可选 | 需独立服务；不用时模型调用走轻量 client |

### 5.2 heron 业务页

- 热榜源、候选流、生产台、审片台、发布台、原型项目、用量、健康。
- 单入口；菜单由服务端下发；无「租户台 / 平台台」两套控制台。

### 5.3 明确不做

- 租户台、平台台、租户套餐、配额拦截、计费、发票、自助注册。
- 自建 RBAC、自建在线会话、自建平台审计。
- 多控制台与两套菜单。

## 6. 旧 → 新基座对照

| # | 旧 heron（NestJS） | 新基座（RuoYi 6.0） | 处置 |
|---|---|---|---|
| 1 | 多租户 + Postgres RLS | 无（6.0 整体移除） | **砍掉**：单租户，表不带 `tenant_id` |
| 2 | 租户台 + 平台台双控制台 | 单管理台 + 服务端菜单 | **合并** |
| 3 | 自建 JWT + `session_version` + `sessions` 表 | Sa-Token + 在线用户 | **改用基座** |
| 4 | BullMQ（可选）+ DB 租约 | Spring `@Scheduled`；SnailJob 可选 | **改用**；渲染执行器另定 |
| 5 | 七牛 Kodo 适配器（`packages/storage`） | `ruoyi-common-oss`（AWS S3 SDK） | **改用 S3 协议**；七牛需确认 S3 兼容性，否则本地盘或换 S3 存储 |
| 6 | 单一 OpenAI 兼容 model client | Spring AI / SnailAI（可选） | **待定**；建议保留轻量 client，避免额外中间件 |
| 7 | Zod 契约（前后端同源） | Bean Validation + 业务校验 | **改用**；前后端契约用 OpenAPI/类型生成补齐 |
| 8 | Drizzle schema + 迁移 | MyBatis-Plus + SQL 脚本 | **改用** |
| 9 | 雪花 id + 审计四件套 + `del_flag` | MyBatis-Plus `ASSIGN_ID` + `BaseEntity` + 逻辑删除 | **基座已提供** |
| 10 | SSE 进度 | Spring `SseEmitter` / WebSocket | **改用** |
| 11 | 单镜像跑 api + worker | `ruoyi-admin` Dockerfile + compose | **改用**；渲染/发布执行器需另起进程或进镜像 |
| 12 | `ACTIONS × MIN_ROLE` + 服务端菜单 | RuoYi 角色/菜单/按钮权限 | **改用** |
| 13 | 用量台账（token/渲染/发布） | 自建 `usage_record`（RuoYi AI 统计仅覆盖 SnailAI） | **保留自建** |
| 14 | 平台设置、平台审计 | `sys_config` + 操作日志 | **改用** |
| 15 | 租户套餐、额度闸 | 无 | **砍掉** |
| 16 | 对象键 `tenants/<id>/<date>/...` | S3 key 规则 | **可选沿用**（去掉租户前缀） |

### 代价与变化（必须知道）

1. **Redis 成为必需**：Sa-Token / Redisson 依赖 Redis；旧方案里 Redis 是可选的。开源「零额外中间件」的目标因此改变。
2. **数据库默认 MySQL**：基座提供 Postgres / Oracle / SQLServer 脚本，但默认与测试路径是 MySQL；旧的 Postgres + RLS 口径作废。
3. **前端与版式不再天然同栈**：旧方案用同一套 Vue SFC 出片；新后端是 Java，渲染执行器需要单独选型（见 D4）。
4. **多租户能力归零**：未来若要恢复 SaaS，需要重新引入租户模块与隔离方案，不能靠旧文档。

## 7. 非功能与合规

### 7.1 部署

- 单机 Docker Compose：`ruoyi-admin` + MySQL + Redis；可选 SnailJob / SnailAI / MinIO。
- 初始化：导入基座 SQL，创建管理员；业务表迁移用版本化 SQL。
- 业务产物默认落本地盘（`data/videos`、`data/protos`）；需要远端再配 S3。
- 单机无高可用是接受的代价；重启恢复靠状态机与租约。

### 7.2 鉴权与账号

- Sa-Token 会话；验证码可开；密码错误锁定。
- 初始超管用户名 `admin`；口令下限 10 位（沿用定案）。
- 发布凭据与模型密钥不进业务表明文：密钥加密/掩码，发布凭据只存路径 + sha256。

### 7.3 审计与「不静默」

- 基座操作日志/登录日志 + 业务留痕（闸结果、确认三样、发布回执、原型版本、用量）。
- 每个失败必须可回答：哪条闸、哪段输入、为什么。
- 不允许自动改稿、自动跳过闸、静默降级。

### 7.4 AIGC 合规

- mp4 写入 `AIGC` 元数据。
- 画面/描述带「内容由 AI 生成」声明。
- 姿态文件要求（角标等）按配置执行。
- 合规闸在发布前，缺任一项拒绝且不可跳过。

### 7.5 安全边界

- 热榜抓取：出口白名单 / 解析后 IP 校验（SSRF）；开放注册或对外托管前必须补。
- 产物下载：鉴权 + 路径包含性校验；对象存储用短时效签名。
- 原型下载：按项目授权，越权返回 404。
- 模型密钥：页面只回显「是否已配置」，不回显明文。

### 7.6 保留与恢复

- 成片按保留天数清理；失败现场保留。
- 原型旧版本不删。
- 任务租约过期可重领；发布重试前先查外部状态。

### 7.7 性能口径
