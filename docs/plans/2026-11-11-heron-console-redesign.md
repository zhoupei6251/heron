# Heron 控制台重构计划

**范围**：前端信息架构与页面重构。后端只列「页面反推出的契约缺口」，编辑引擎本身的改造以
[编辑引擎实现计划](2026-11-11-editorial-engine-implementation.md) 为准，本文不重复。
**前置事实**：视觉已拍板（「克制的生产台」、主色青 `#1b6c80`、令牌层 `tokens/_brand.scss`）。
本文不讨论颜色、字体、动效，也不做视觉重设计。

---

## 0. 一句话判断

后端缺的是**决策链**，前端缺的不是页面而是**结构**。

现有 5 个页面（3054 行）把「发现 → 创作 → 审核 → 发布」压进了 2 个列表页 + 若干长抽屉：
`news/work/index.vue` 849 行、`proto/index.vue` 1052 行，两页都是「列表 + 抽屉里什么都有」。
重构的动作是**把抽屉拆成页面**，不是再堆一层页面。

## 1. 现状盘点（已验证）

| 现有页面 | 行数 | 现在的职责 | 问题 |
|---|---|---|---|
| `news/source` | 339 | RSS/热榜来源管理、采集 | 合理，只补「连续失败」告警 |
| `news/candidate` | 317 | 候选列表 + 认领 | 只有列表，没有「这条值不值得做」的判断依据 |
| `news/work` | 849 | 草稿/版本/预览/审片/发布 | 一个抽屉承担 4 个岗位的动作 |
| `production` | 497 | 任务、阶段、错误、用量 | 有价值，但和 work 页重复展示任务详情 |
| `proto` | 1052 | 原型全流程 | 能用，不在本次范围 |

**后端控制器只有 9 个**（news / work / source / candidate / production / proto / metric / auto / health）。
因此有三类页面**现在没有数据源**：

| 想要的页面 | 缺什么 | 结论 |
|---|---|---|
| 编辑策划 | 决策记录只存在 `heron_auto_slot.detail` 一段文本里 | 等后端批次 2 |
| 数据集管理 | 无 controller；数据源靠 SQL 种子 + Java 适配器维护 | 需新建 |
| 模板中心 | 模板是 `data/templates/` 下的文件，无注册表 | 需新建 |
| 内容效果 | `heron_news_metric` 有表无数据 | 只能先空态 |

`heron_auto_slot` 主键是 `(slot_date, slot_time)`，没有自增 id。**「编辑运行」不新建表**，
就地扩展这张表即可——它已经在记 `status / detail / work_id`，只缺结构化字段。

## 2. 三条原则

1. **视觉不再讨论。** 新页面只消费 `_brand.scss` 的语义令牌，不写死颜色；「生产轨道」作为签名元素复用。
2. **列表负责发现，详情页负责操作。** 主要业务动作离开抽屉。
3. **作品是业务对象，任务是执行记录。** 用户看「作品做完没有」，运维才钻「哪个阶段失败了」。

补一条被上一版方案忽略的：**同一条数据只在一个页面有主视图**。
任务详情归生产任务页，作品状态归作品页，两边用链接互跳，不各画一份。

## 3. 目标导航

```
Heron 工作台
├── 选题雷达                          [已交付] news/topic → 列表 + 详情页
├── 编辑策划                          [已交付] editorial
├── 视频作品                          [已交付] news/work → 列表 + 工作室页
├── 审片中心                          [已交付] review
├── 发布记录                          [已交付] publish
├── 新闻来源                          [复用] news/source
├── 数据集                            [已交付] asset/dataset
├── 视频模板                          [已交付] asset/template
├── 生产任务                          [复用] production
└── 原型工坊                          [复用] proto，本次不动
```

**最终是平铺，没有二级目录。** 原计划分了创作中心 / 资产中心 / 运行时三组。落地时判定：
若依的目录靠 `ParentView` 展开，子路径会被拼成 `/heron/<dir>/<child>`，且这套展开逻辑
在权限 store 里改写实际路由；本轮没有浏览器验收条件，冒这个风险不划算。等有一轮真机验收后再分组。

**和上一版提案的差异（都是有意的减法）**

- 去掉「AI 与系统管理」一级：模型配置、权限、审计都在基座里，重复建菜单只是把同一件事做两遍。
- 去掉「自动化中心」一级：自动模式当前只有开关 + 暂停 + 槽位，一张卡片就能表达，塞进运行时。
- 去掉「媒体素材库 / 音频资源库」：现在没有素材上传与版权管理体系，先不建空壳页面。
- 去掉「发布日历」：现在只有一个发布出口且默认 sandbox，日历没有信息量。
- 原型工坊不重做：1052 行已经能跑，重做不产生新能力。
- 审片中心**不新建后端**：`heron:newsWork:review` 权限和审片接口都已存在，缺的只是独立页面。

## 4. 六个页面的骨架

### 4.1 首页（改造）

四块，自上而下：

1. **今日一行**：今日选题数 / 生产数 / 待审 / 已发布 / 本月模型用量。每格点进去带到对应页并带上筛选。
2. **生产轨道**（签名元素）：`发现 → 策划 → 写稿 → 渲染 → 审片 → 发布`，每格显示今日数量和卡住的最久时长。
   复用 `StageTrack.vue` 的判据，闸画在进入那一格之前。
3. **待我处理**：待审片队列、失败任务、连续失败的来源，按「需要人」排序。
4. **今日编辑运行**：最新几条 `heron_auto_slot`，显示走了哪条线、为什么、产出哪条作品。

数据源：现有 `production` / `newsWork` / `newsSource` / `auto` API 够用，无需新接口。

### 4.2 选题雷达（改造 `news/candidate`）

列表页回答「今天有什么值得做」，详情页回答「凭什么值得做」。

- **列表**：候选卡片而非纯表格。每张卡有标题、来源、热度、来源证据条数、是否有正文、
  是否已匹配到数据集、是否历史做过（重复选题要高亮）。
- **筛选**：全部 / 有正文（可走解说线）/ 有数据集匹配（可走看板线）/ 已认领。
  「有没有正文」「有没有数据」这两个筛选项就是两条生产线的入口条件，直接映射后端候选池边界。
- **详情页**（新建路由 `/heron/topic/:id`）：事件时间线、来源证据逐条列出（含抓取时间、正文摘要、内容指纹）、
  AI 判断依据、可用的数据集候选、历史相似选题。主操作：认领并指定方向 / 暂存 / 忽略。

### 4.3 编辑策划（新建，依赖后端批次 2）

这个页面的本质是**编辑运行记录的可解释视图**，不是定时任务配置页。

- **左栏**：按日期分组的运行列表，每行一个 `heron_auto_slot`（日期 + 时刻 + 状态 + 走了哪条线）。
- **右栏**：选中的那次运行展开成决策链：
  1. 候选池快照（当时看到的热榜前 N + 有正文的 RSS + 数据集候选）
  2. LLM-1 总编辑：`selectedLine / reason / editorialIntent`
  3. LLM-2 线内编辑：选中的候选、数据集、模板
  4. LLM-3/4/5：标题候选、正文、审稿结论
  5. 产出：作品链接
- **动作**：对当天尚未运行的时刻，支持「现在跑一次」（已存在 `tick(slot, manual=true)`）；
  对已产出的，可以「重跑」——重跑是新建一条运行，不覆盖旧记录。

**关键**：这一页能成立的前提是后端把决策**结构化落库**，而不是今天这样拼在一段 `detail` 文本里。
见 §5。

### 4.4 视频作品（改造 `news/work`）

拆成两页：

- **作品列表**（`/heron/work`）：作品卡片，显示城市/题材、当前版本、状态（创作中/待审/已发布）、最近的模型成本。
- **作品工作室**（`/heron/work/:id`，新建路由）三栏：
  - 左：内容结构（选题资料 / 标题候选 / 脚本 / 场景 / 版本历史）
  - 中：编辑与预览（脚本分段编辑、成片播放器、生产进度轨道）
  - 右：创作设置（模板、音色、画幅、时长、质量检查结果）

  第一版**不追求非编体验**：脚本可分段改、可重生成，场景只读展示，版本可对比、可回滚。

### 4.5 审片中心（新建）

左：待审队列。中：成片播放器 + 字幕 + 脚本对照。右：检查清单 + 通过/驳回。

检查清单分两组，对应两条线不同的事实来源：
- 通用：画面异常、字幕错字错位、音画对齐、时长画幅
- 数据看板线：数字与 Java 事实清单是否一致
- 解说线：文案是否超出原文证据范围（对照 `quotes` 的原文片段）

驳回必须选到**具体段落或场景**，不能只写一句话理由——这是以后反哺提示词训练的原料。

### 4.6 资产中心（新建，独立于编辑引擎）

- **数据集页**：数据提供方、数据集、字段、更新频率、授权状态（`unknown` 要显眼标红）、
  最近采集时间、最近一次探测结果、快照样本。**授权 unknown 的数据集在列表上就要拦人**，
  不能让它在页面上看起来和授权明确的一模一样。
- **模板页**：缩略图/预览、模板 key、支持的数据形态、所需字段、画幅、推荐时长、当前哈希、最近使用记录。

## 5. 页面反推的后端契约缺口

按「不做这个，页面就只能是假数据」排序。

| # | 缺口 | 阻塞哪个页面 | 对应后端批次 | 最小做法 |
|---|---|---|---|---|
| 1 | 决策结构化落库 | 编辑策划 | 批次 2 | 扩 `heron_auto_slot`：加 `selected_line / editorial_intent / decision_reason / selection_json / usage_json`，不新建表 |
| 2 | 候选的「素材能力」字段 | 选题雷达 | 批次 2 | 候选返回体加 `hasBody / bodySourceUrl / bodyFetchedAt / contentHash`，由 `NewsCandidateCollector` 在合并时就写清，不再靠 `sourceIdOf()` 看第一条证据 |
| 3 | 审稿结论返回体 | 审片中心 | 批次 4 | `EditorialReviewer` 的 issues 带 `level / quote / suggestion`，随作品详情返回 |
| 4 | 数据集注册查询 | 资产中心 | 独立，不依赖编辑引擎 | 一个只读 controller：列表 + 详情 + 最近快照 |
| 5 | 模板注册查询 | 资产中心 | 独立 | 一张 `heron_video_template` 表，启动时从 `data/templates/` 扫描同步 |
| 6 | 作品返回值补线内选择 | 作品工作室 | 批次 3 | `NewsWorkVo` 带上 `datasetId / templateId / storyAngle` |

**批次 1（恢复解说线）不产出任何前端契约**，前端可以与它并行开工。

## 8. 已拍板：自动生产走「决策即生产」（方案 A，2026-11-11）

`NewsAutoService.tick()` 里总编辑决策完成后**立即** `claimForAuto` + `generateForAuto`，中间不插入人工确认。
编辑策划页因此是**纯追溯视图**：看历史运行、看决策链、对未运行槽位手动触发、对已产出的重跑（新建运行，不覆盖）。

**Why：** `auto-enabled` 默认仍是 `false`，没有人真在跑无人值守，此时加确认环节是为一个未启用的模式做设计。
等自动模式真开起来、看过第一批产出质量，再评估是否引入「待确认计划」。

**How to apply：** 期 2 不实现「待确认」状态、不加确认动作、不处理确认超时。
`tick()` 的状态机保持 `running / produced / skipped / failed` 四态不变。
若将来改判，影响面只有两处：`tick()` 增加一个前置状态，以及期 2 页面多一个队列视图。

## 9. 交付状态（2026-11-11）

期 1–5 的代码全部落地，2026-11-11 晚完成登录后的真机验收。

| 层 | 手段 | 结果 |
|---|---|---|
| 编译 | `mvn compile`（模块 + admin 依赖）、`vue-tsc --noEmit`、`oxlint` | 通过 |
| 运行时注册 | 重启后端后逐条请求新接口 | 5 组接口全部返回 `code:401 登录状态异常`；对照 `/heron/nope` 返回 `code:404 请求地址不存在` |
| 页面 | 登录后逐页打开（整页加载） | 首页、选题雷达、选题详情、编辑策划、视频作品、作品工作室、审片中心、发布记录、数据集、视频模板 全部渲染，控制台无报错 |
| 真实数据 | 各页读取线上库 | 待认领选题 1966、作品 12、发布记录 3、数据集 119（其中授权 unknown 占多数）、模板 13 套且 LOCK 全有效 |

**验收查出并修掉的两处**

1. 选题摘要里是 RSS 原始 HTML（`<p data-vmark=…>`），直接渲染会把标签显示出来。改为剥标签：
   `views/heron/heron-text.ts` 的 `plainText()`，不用 `v-html`——正文来自外部站点，注入面太大。
2. 审片队列和发布记录把 `inputSnapshot` 一起返回，**单行 76 KB**（含整篇正文与证据），一页十行近 1 MB，
   打开队列要等两三秒。列表视图改为不返回 `inputSnapshot` / `script`，正文只在单版本详情里给。

**验收环境的一个坑**：预览标签页在后台不绘制时，Vue 路由的 `transitionend` 不触发，
旧页面会停在 `v-leave-active`，表现为「URL 变了但页面不换」——连 `/system/user` 也一样，
是环境问题不是代码问题。验证一律用整页加载，别用 SPA 点击。

### 后端新增

| 能力 | 位置 | 说明 |
|---|---|---|
| 决策结构化落库 | `heron_auto_slot` +5 列 | `selected_line / editorial_intent / decision_reason / candidate_id / pool_json` |
| 编辑运行只读视图 | `EditorialController` + `EditorialRunService` | `GET /heron/editorial/runs`、`/runs/detail` |
| 审片队列 | `NewsWorkController` `/review/queue` | 跨作品待审版本，不预先剔除渲染失败的 |
| 发布记录 | `NewsWorkController` `/published` | 有发布事实的版本 |
| 数据集注册表 | `DataSourceController` | 只读；登记仍走 SQL 迁移 |
| 模板目录 | `TemplateController` | 读 `data/templates` 的 LOCK，不建表 |

### 落地时改掉的三处计划

1. **不分组**（见 §3）：没有浏览器验收条件，不动 `ParentView` 展开。
2. **资产中心不建注册表**：模板本来就是目录，加一张表只会多一处要同步的真相。
3. **审片队列按 `review_status` 过滤，不按「可审」过滤**：`task_status` 不在版本表上，
   内存过滤会打乱分页。渲染失败的版本照列并标红，比藏起来更诚实。

### 仍然缺的

- **编辑策划看不到线内编辑与审稿**：`tick()` 目前只有总编辑一次决策，批次 3/4 的
  线内编辑、独立审稿还没接，所以页面上没有那两段。等批次 3/4 落地后在 `markDecision` 旁补记。
- **首页没有「生产轨道」和「今日编辑运行」**：前者要按阶段聚合 `steps[]`，后者要今天的运行记录，
  都没有现成接口。加这两个区块时直接用 `EditorialController` 的列表。
- **候选的「素材能力」仍然靠客户端推断**：`hasBody` 是解析 `evidence.items[].sourceUrl` 得到的，
  后端没有 `hasBody / bodySourceUrl / contentHash` 字段（§5 缺口 2）。只做展示、不做筛选。
