# 三套数据视频风格的差异化视觉语言规范

> 2026-11-19。纯设计稿：不改模板、不改生成器、不改 `data/templates` 下的任何产物。
> 目标：让「专业新闻 / 数据调查 / 动态数据解释」三套风格形成**真正不同的视觉语言**——不同的信息组织方式、不同的画面焦点、不同的数据展示手法、不同的转场节奏——而不是同一张骨架换三套颜色。
>
> 事实基础：`data/templates/_shared/tokens/*.css`、`data/templates/layouts/*/*.css`、`data/templates/_gen/behaviors/{chart,focus}.js`、`data/templates/_gen/motion.js`、`data/tools/build-templates.mjs`、`docs/reference/video-craft/*`、`ruoyi-modules/ruoyi-heron/src/main/java/org/dromara/heron/service/impl/` 下的 `NewsProductionPipeline` / `NewsTemplatePicker` / `DatasetVisualFocus` / `DatasetFacts` / `DatasetScriptContract`（均于 2026-11-19 在 `dev` 分支实读）。

---

## 0. 一句话

三套风格现在的差别**九成在令牌里**：底色、字号、圆角、栅格、动效时长。结果是「三张不同颜色的同一张版式」。本文把差异拆成四层——**版式骨架（谁占哪块画面）→ 信息层级（观众先看什么）→ 图表手法（同一份数据长什么样）→ 节奏（什么时候推进、什么时候停）**——并逐条标注：哪些差异只改样式令牌就能落地，哪些必须改 `focus.js` / `chart.js` 的行为，以及在现有生成器与 `LOCK.json` 冻结机制下怎么落地而不破坏可重放。

### 1.3 三个必须先承认的结构性事实（决定了设计能走多远）

**事实 1：图表是常驻层，不是分屏元素。**
`chart.js` 在 setup 阶段一次性把整张图画进 SVG，之后只做 `scale 1 → 1.04` 的慢推（`chart.js:46`）。`#chart-slot` 的时间窗是 `0 → 整片时长`，`applyTimeline` 也只把它改写成 `0 → totalSeconds`（`NewsProductionPipeline:994`）。**所有分镜共用同一张图**，`focus.js` 只在图上叠光晕/连线、并把非焦点条目压暗。

> 结论：「每屏换一张图」在当前架构下不存在。想让三套风格在「数据展示手法」上真正不同，动效层做不到，只能在**同一张图上做不同的呈现与聚焦**——除非改 `chart.js` 行为（本文第 5 节 L4）。

**事实 2：焦点语义是全局统一的，与风格无关。**
`DatasetVisualFocus.forScene()` 从旁白里的 `{{facts.*}}` 引用推出 `mode ∈ {change, comparison, range, item, leader, latest, overview}`，这个 mode 同时决定 `focus.js` 画什么（`focus-link` 连线、`focus-halo`/`focus-ring` 圈点）、KPI 显示什么、条目压暗什么。**风格不参与焦点决策**。

**事实 3：样式差异的合法出口只有四个文件。**
`build-templates.mjs` 的 `styles()` 按固定顺序拼接：`base.css` → `tokens/<style>.css` → `behaviors/chart.css` → `layouts/<style>/<layout>.css`。
关键结论：**版式 CSS 排在 `chart.css` 之后**，所以一份 per-style 的版式 CSS 可以覆盖 `chart.css` 里的 `.series-line` / `.bar` / `.axis` 等规则，而**不必改共享的 `chart.css`**。这是当前架构里成本最低的差异化杠杆。

## 2. 三套风格的视觉语法

### 2.0 一张总表

| | A 专业新闻 | B 数据调查 | C 动态数据解释 |
|---|---|---|---|
| **一句话** | 「三秒内告诉你现在是什么情况」 | 「这件事不对劲，我带你一步步看」 | 「这组数字拆开看是这样的」 |
| **信息组织** | 播报流：结论 → 环比 → 榜位，线性播报 | 证据链：现象 → 异常点 → 区间位置 | 指标解剖：数值 → 分布 → 排序，同屏多指标并置 |
| **画面焦点** | 数字本身（KPI + 末点） | 异常点（极值被圈出） | 关系（整条曲线 / 名次分布） |
| **图表角色** | 佐证（图表给播报条让位） | 物证（图表是唯一硬证据） | 主角（图表占据主视区） |
| **信息密度** | 低—中（每屏 1 个数 + 1 句） | 低（每屏 1 句 + 1 个圈点） | 高（数字 + 曲线 + 段落 + 元信息同屏） |
| **节奏** | 快：0.42s 进、0.26s 换 | 慢：0.90s 进、0.50s 换 | 中：0.55s 进、0.32s 换 |
| **观众动作** | 看一眼数字 | 盯住那个圈点 | 读图（趋势、排序） |

### 2.1 版式骨架：四类画面各占多少

以 1080×1920 计。以下为**三份版式 CSS 的实算值**（不是注释里的估算值——注释里的纵向预算与 CSS 实值已有偏差，见 §7 假设 3）：

| 画面 | A 专业新闻 | B 数据调查 | C 动态数据解释 |
|---|---|---|---|
| 标题区 | 130 → ~530 | 150 → ~590 | 104 → ~500 |
| 图表区 | 540–1060（520px） | 600–1060（460px） | 500–1050（550px） |
| 场景区 | 约 1200–1500（**下三分之一带**，`bottom:420`） | 1080–1500 | 1075–1510 |
| 底栏（进度 + 来源 + AIGC 角标） | ~1542–1620 | ~1532–1610 | ~1542–1620 |
| 底部 300px 空带 | 留给平台 UI | 同 | 同 |

**三套必须保持不同的骨架规则：**

- **A（播报）**：`#title-card` 与 `#chart-slot` 是「信息层」，`.scene` 是「播报条」，两者用**上下分区**关系，不是主次关系。播报条整幅通栏（`left:0;right:0`），带半透明深色底 `--band` 与 10px 强调色立标；屏次编号占左栏 120px，正文占右栏。**播报条永远不许被图表挤掉**——这是 A 的签名结构，任何版式改动先保它。
- **B（调查）**：`.scene` 两侧缩进到 `--pad-frame` 并加 2px 竖引线，文字从引线右侧起排；标题区最高（100px 标题 + 96px KPI）。图表被**主动下压到 600**（"图表是证据不是主角"）。收尾 `#closing` 用 `border-top: 2px solid var(--accent)` 而不是面板框——B 不用卡片。
- **C（解释）**：图表最高最宽，标题最小（92px）但最靠上（104px），信息密度最高；`.scene` 通栏，屏次序号本身染强调色（`color: var(--accent)`）当作节奏锚点；`#closing` 是带 10px 左侧强调条的 `--panel` 面板（**C 是三套里唯一用面板盒子的**）。

**结论：三套的骨架差异已经存在，但需要被"命名"和"守住"。** 本文建议在版式 CSS 顶部各留一行「本套骨架不变量」注释（例：A 的「播报条高度 ≥ 280px 且 bottom ≤ 440px」），并把不变量写成可断言的形式（见 §5 L1）。

### 2.2 字体层级

现状三套的**字族完全相同**（都是 `Noto Sans SC`，且只有 `Regular` 一个 otf 文件声明 `font-weight: 100 900`——`base.css:3-9`），层级全靠字号与字重硬撑。

三套应当用**不同的字重对比轴**而不是不同的字号表：

| 层 | A 专业新闻 | B 数据调查 | C 动态数据解释 |
|---|---|---|---|
| 主标题 | 86px / 900 | 100px / 900 | 92px / 800 |
| 场景领句 | 50px / 800 | 50px / 800 | 54px / 700 |
| 场景正文 | 34px / 400 | 36px / **300** | 38px / 400 |
| KPI 数值 | 72px / 800 | 96px / 800 | 64px / 800 |
| 标签 / 注记 | 28px | 29px / 28px | 28px |
| 字距（kicker） | 0.24em | **0.32em** | 0.16em |
| 标题字距 | -0.015em | **-0.03em** | -0.02em |

- **A 的轴是「密」**：字号最小、字距最松、rule 最粗（8px），靠高对比度和粗线建立权威感，不靠留白。
- **B 的轴是「重」**：标题最大最黑，正文 300 字重（全场唯一的轻正文），引线 2px，靠字重差 300↔900 建立编辑气质。
- **C 的轴是「稳」**：字重差最小（700↔400），字号最平，靠等宽数字（`tabular-nums`）和网格建立秩序感。

**已知缺口（设计指出，不在本轮实现）**：`--font-body` 与 `--font-num` 三套完全相同（都是 `Noto Sans SC`），而 `video-craft/frame-design.md` 明确要求「不要两个无衬线配对，跨界：衬线 + 无衬线，或无衬线 + 等宽」。若要给 B 换衬线体，必须解决两件事：① 自带 `@font-face`（内置 18 字族不含中文衬线；`Noto Sans JP` 是唯一的内置中文）；② 渲染端离线确定性。**本轮不改字体**，但把「B 未来可能引入衬线」记为一条可执行的后续方向，并规定：引入衬线必须**只用于标题与引线**，正文与数字仍用无衬线，且必须同步更新 `LOCK.json` 的 `fontSha256`（字体进资产清单，`build-templates.mjs:350` 会把共用字体哈希写进每个模板的 `assets-manifest.json`）。

### 2.3 配色策略：语义色怎么用，强调色什么时候用

三套目前都是**单强调色 + 一个 down 色**，语义色体系尚未建立：

| | 强调色 | `--down` | `--muted` / `--muted-2` | `--rule-*` |
|---|---|---|---|---|
| A | `#e23b2e` | `#ef7a6a` | `#8ea6c0` / `#a9bdd4` | 白 0.16 / 0.20 / 0.38 |
| B | `#d9a05b` | `#c9705f` | `#8a8378` / `#a69d90` | 米白 0.14 / 0.18 / 0.34 |
| C | `#18b7c9` | `#e06c5a` | `#7f949b` / `#9fb0b6` | 米白 0.12 / 0.14 / 0.28 |

**本轮要确立的语义色规则（三套共用规则、三套不同取值）：**

1. **强调色只标"当前这一拍的主角"**。允许出现强调色的位置恰好三处：① KPI 数值（`focus.js` 已如此实现，负值改用 `--down`）；② 焦点圈点与焦点连线（`.focus-ring` / `.focus-halo` / `.focus-link`）；③ 版式签名元素（A 的立标与进度条、B 的引线端头、C 的序号与色条）。
2. **同一个画面里强调色的面积 ≤ 12%**。A 靠 10px 立标 + 6px 进度条达标；B 靠 2px 引线 + 2px 顶部线达标；C 靠 3px 色条 + 序号文字达标。三套都不允许整块面板用强调色填充。
3. **涨跌语义必须带符号**：`▲ / ▼` + 数字（`focus.js` 的 `result.detail` 已经这么写）。颜色只做强化，不单独承载信息——这条来自 `video-craft/quality-gate.md` 的「绿红只表示好坏，且必须带 ▲▼ 与文字」。
4. **每套需要一个"第二强调"用于多系列**：C 的 `seriesColor()` 从 `--accent` 的色相左右摆动生成多系列颜色（`chart.js:74-96`），A 与 B 走同一套逻辑，因此 A 的多系列会变成红色的摆动、B 变成琥珀的摆动——**这在三套里都成立，是免费的一致性**。但摆动幅度上限 76° 色相、`S=64%`，在暗底上多系列会靠明度区分；建议后续给每套加一组**分类色 token**（A 冷灰蓝系、B 暖褐系、C 青—琥珀—青紫），本轮只在设计里定位置，不进代码。

**「什么时候用强调色」的判据（三套共用）**：
> 强调色只在**这一屏要观众看的那一个东西**上出现。观众这一屏该看三样东西，就要三样都上强调色；只该看一样，就只许一处上强调色。

### 2.4 同一份数据在三种风格下长什么样

用**同一份快照**（风格 A 的默认数据集：持仓量 `wide`，12 期周频，78.2 → 62.4 万手，`change = -15.8`，`change_pct = -20.2%`，`max = first`，`min = last`）分别在 A / B / C 下呈现。**数据、facts、旁白事实引用全部不变，只有画面不同。**

#### A 专业新闻 —— 「今天这个数」

```
┌──────────────────────────┐
│ ▌市场播报                │  ← 顶部 kicker，红色立标 10×34
│ 十二期持仓变化            │  ← 86px/900
│ ████████████████         │  ← 8px 满幅红条
│ 62.4 万手  ▼20.2%        │  ← KPI，72px，负值用 --down
│                          │
│   ╲                      │  ← 图表压到 540–1060，
│    ╲___                  │    单线 8px，末点 + 数值标签
│        ●                 │
│ ┌──────────────────────┐ │
│ │01│ 区间首末下降       │ │  ← 下三分之一播报条（通栏）
│ │  │ 最新一期持仓为…    │ │    屏次在左栏 120px
│ └──────────────────────┘ │
│ ▬▬▬▬▬▬▬▬▬  内容由 AI 生成 │  ← 底栏
└──────────────────────────┘
```

- **信息组织**：结论先行。图与数字只回答「现在是多少、比区间起点如何」，历史由旁白口播承担。
- **画面焦点**：**末点**。`focus.mode = latest/change` 时 `focus.js` 给末点套 halo，KPI 同步显示该值。
- **图表手法**：满幅面积图（`series-area` 16% 透明）+ 8px 折线 + 末点圆点 + 末点数值标签；极值标注**只标"最高"且用强调色**——因为播报只关心"有没有到过高点"。
- **镜头节奏**：入场 0.42s，`power4.out`（最利落）。图在前 1.5s 画完（`introDrawDuration = max(0.7, min(8, openingEnd - 0.8))`，`chart.js:44`），之后不推进，**观众的时间全给播报条**。场景换场 0.26s，`power2.in`，硬切感。
- **本套专属建议（需改 `chart.js`，L4）**：末点之后的折线应当"退场"（降透明到 40%），把亮度让给播报条——即"图表是背景、播报是前景"。今天是全亮折线贯穿到片尾。

#### B 数据调查 —— 「这件事不对劲」

```
┌──────────────────────────┐
│                          │
│ ▎深度调查                │  ← kicker，2px 竖标 + 0.32em 字距
│                          │
│ 十二期价格变化            │  ← 100px/900，字距 -0.03em
│ ────                     │  ← 2px 强调色短线（仅 140px 宽）
│                          │
│ 0.68 元/W                │  ← KPI 96px/800（全场最大）
│                          │
│      ╲___╱___            │  ← 图表 600–1060，细线 4px，无面积填充
│          ● ← 最低点      │    焦点圈点（halo 18px 光晕）
│ ┌ ──────────────────── ┐ │
│ │02  最近五期下行        │ │  ← 缩进 + 2px 竖引线
│ │    最近五期从…         │ │    正文 36px/300
│ └ ──────────────────── ┘ │
└──────────────────────────┘
```

- **信息组织**：**异常优先**。第一屏就把「区间最低点」推到台前（`mode = range`），而不是先讲总量。
- **画面焦点**：**极值点**。`focus.js` 的 `paintEvidence` 对 `range` 模式给 `min`/`max` 打 halo + ring，并把**其余曲线整体压暗**——但压暗值现在写死 0.55，B 需要更狠（见 §5 L3）。
- **图表手法**：**只有线，没有面积**（`.series-area` 需要在 B 的版式 CSS 里覆盖为 `fill-opacity: 0`）；线宽从 8px 降到 4px；坐标轴标签降到 `--muted` 且不抢眼；`chart-note`（"份额 %" 这类）可保留——它是口径，B 需要口径可见。
- **镜头节奏**：入场 0.90s，`power2.out`；换场 0.50s，`sine.in`；环境层 `--dur-ambient: 11s`（最慢），颗粒 0.34 制造胶片质感。**图在第一屏不画完**：`introDrawDuration` 与 `openingEnd` 绑定（`chart.js:41-45`），首屏越长图画得越久，B 的"边讲边画"感由此而来。
- **本套专属建议（需改 `focus.js`，L3）**：B 的非焦点压暗应接近"退场"（亮度 0.25–0.30），并让**焦点点有一个 0.9s 的放大落定**（当前 halo 是静态 SVG，没有落定动画）。

#### C 动态数据解释 —— 「这组数字是这样的」

```
┌──────────────────────────┐
│ ▬ 数据观察                │  ← kicker，56×8 色块
│                          │
│ 金价创阶段新高            │  ← 92px/800
│ ████████████████         │  ← 3px 强调色条
│ 4113.34 USD/oz ▲3.14%   │  ← KPI 64px（与 A 的 72 / B 的 96 拉开）
│                          │
│  ~~~~~~~~~~~~~~~~~~~~    │  ← 图表 500–1050，最宽最高
│   ╱╲    ╱╲      ●        │    72px 栅格 + 光晕 + 颗粒 0.16
│  ╱  ╲__╱  ╲___╱          │    最高/最低双标注
│ ┌──────────────────────┐ │
│ │01  金价站上关键位      │ │  ← 通栏，序号染强调色
│ │    最新收于 4113.34…   │ │    正文 38px/400，3 行
│ └──────────────────────┘ │
│ ▬▬▬▬▬▬▬▬  内容由 AI 生成 │  ← 8px→6px 进度条 + 来源右对齐
└──────────────────────────┘
```

- **信息组织**：**一屏多要素并存**。标题 + KPI + 完整图 + 段落 + 场景号 + 来源同时在场，信息密度最高，靠留白以外的手段分区。
- **画面焦点**：**关系**。`mode = change` 时 `focus.js` 画一条 `focus-link`（虚线）把首末两点连起来——观众看的不是某个点，是"从这儿到那儿"。`mode = comparison` 时取 rows 首末两项并置。
- **图表手法**：**面积 + 折线 + 双极值标注 + 末点脉冲**（`chart.js:483-487` 的有限次呼吸，是三套里唯一的持续动画元素）。栅格 72px 提供刻度感。
- **镜头节奏**：入场 0.55s `power3.out`；换场 0.32s；环境层 7s（最快）——网格漂移 + 光晕脉冲 + 颗粒闪烁三件事叠加，是三套里唯一"背景一直在动"的。
- **本套专属建议（需改 `chart.js`，L4）**：C 的 `--fs-data` 只有 64px（小于 A 的 72、B 的 96），但 C 的 KPI 后面还要挂 `--kpi-change` 与 `#focus-caption`（口径说明）。C 的口径行应该被提升为图表内的一行小注而不是挂在标题区——但 `#focus-caption` 目前写在 `#title-card` 里（`skeleton.html`），挪位置需要动骨架或版式定位。

### 2.5 镜头与动效节奏

现状 `motion.js` 只有三种动作，且注释里写死了原则：**「风格差异靠改令牌而不是另写一套动画——否则三套风格很快就会长成三份真相」**。本文遵守这条原则，只在**动作序列**层面提出差异化需求，并全部归到 §5 的实现分层里。

| 动作 | 现状 | A 播报 | B 调查 | C 解释 |
|---|---|---|---|---|
| **标题进场** | `enter("#title", {dir:"up"})` 0.42–0.90s | up，快 | up，慢，带 0.03em 字距收紧 | up，中速 |
| **分隔线** | `scaleX 0→1`，起点 0.45s | 满幅 8px 红，横切 | **仅 140px 短线**，像书签 | 满幅 3px |
| **KPI** | `enter("#kpi",{dir:"up"})` 0.35s + 数字滚动（`focus.js` 1.2s cubic-out，仅片头） | 数字滚动 + 落定 | 数字滚动更慢（建议 1.6s） | 数字滚动 + 落定后接口径行 |
| **图表绘制** | `introDrawStart 0.35s`，时长与首屏长度绑定 | 1.2s 画完（快） | 与首屏同长（慢，边讲边画） | 与首屏同长 |
| **场景换场** | `swap()`：入 `y:26` 0.42–0.90s / 出 `y:-14` 0.26–0.50s | 硬切感强（出 0.26s） | 慢出（0.50s），像翻页 | 中速 |
| **背景** | `ambient()` 三种：drift / pulse / flicker，`--dur-ambient` 决定周期 | 8s，轻 | 11s，最慢最沉 | 7s，最快最活 |
| **遮罩 / 揭示 / 重音** | **不存在** | 建议：播报条用「自下而上的遮罩上推」 | 建议：焦点点用「遮罩擦除」逐点揭示 | 建议：数值用「揭示 + 重音」 |

**「遮罩 / 揭示 / 重音」是三套风格真正能拉开差距的地方，也是当前 `motion.js` 完全空缺的地方。** `video-craft/motion-and-transition.md` 的动词表给了现成的动效词汇：

- **A 播报**（动词：PUSHES / CUTS）：新播报条自下往上**推**进画面（`y: 100% → 0`），旧条直接**切**走（不做淡出）。转场类型 = 硬切 / Push。
- **B 调查**（动词：DRAWS / UNCOVERS）：焦点点不是"出现"，是**被揭示**——用 `clip-path: inset()` 沿曲线方向擦出。转场类型 = 溶解 / 焦点拉动。
- **C 解释**（动词：COUNTS UP / PULSES）：数值先滚动后**重音**（一次 1.15× 过冲，`back.out(1.4)`），极值双标注错时入场。转场类型 = 缩放交换。

**节奏型命名（`video-craft/story-and-rhythm.md` 要求先命名再实现）：**
- A：`快-快-停`（播报-播报-留白）
- B：`慢-停-慢-停`
- C：`推-解-重音`

### 2.6 字幕与图表的相对位置

**重要事实：Heron 当前没有独立的字幕层。**
画面上的文字是模板骨架里的 `.lead` / `.body`（内容就是旁白文本），字幕以 `subtitles.json` 旁挂产物形式存在（`NewsProductionPipeline:174-176`），时间线是**cue 级**（`NewsNarrationTiming`，edge-tts WebVTT 边界 + 字符偏移插值，长 cue 直接报错而非出片）。画面文字与图表的相对位置**完全由版式 CSS 决定**，所以"字幕与图表的相对位置规则"在本项目里就是"场景文字块与图表槽的版面关系"。

三套的规则：

| | 场景文字位置 | 与图表的关系 | 底部保留 |
|---|---|---|---|
| A | 图表**下方**，通栏播报条内（`bottom:420`，`.scene` 通栏） | **上下分区，互不重叠**；播报条永远不侵入 1060 以上的图表区 | 420px |
| B | 图表**下方**，但缩进 + 2px 竖引线（`left/right: var(--pad-frame)`） | **上下分区 + 视觉隔离**：引线把文字从图表区"断开"，观众不会把正文当成图表的注解 | 420px |
| C | 图表**下方**，通栏，序号染强调色 | **上下分区**，但 C 的文字密度最高（38px/3 行），必须保证 `.body` 的 `max-height` 与 `line-clamp` 不被顶到图表区 | 410px |

**三条三套共用的硬规则：**

1. **底部 300px 永远空着**，那是平台 UI（评论按钮、账号信息）的地盘。三套的 `#bottom-bar` 都在 `bottom: 300px`（A / C）或 `310px`（B），恰好在这条线之上。**任何版式改动不得下探到 300px 以下。**
2. **图表区与场景区之间必须有一道视觉断点**：A 是 8px 红条（分隔线本身就是断点）、B 是 2px 引线、C 是 3px 色条 + 序号。断点不能只靠留白。
3. **场景文字永远不能与图表区重叠**。现状靠 `#chart-slot` 与 `.scene` 的固定 `top/bottom` 天然隔开，且 `.lead` / `.body` 有 `max-height` + `-webkit-line-clamp` 兜底。**若 B 未来把图表区加高（比如加口径条），必须同步重算 `.scene` 的 `top`，否则正文会被裁。** 这是三份版式 CSS 顶部注释里写的"纵向预算"要维护的原因。

**与 `video-craft/caption-and-audio.md` 的差异（必须记账）**：该文建议竖屏字幕距底 600–700px。三套的播报条底部在距底 420px（文字实际底缘约 430–470px），**比建议值更靠上**。本设计不改动这一点（改它会让场景区进一步压缩，且当前无「字幕层」这个对象），但把它列为一条**已知的、有意偏离**，理由是：三套的文字是「版面元素」而非「字幕」，它与图表、进度条构成一个整体版面，按 600–700px 的字幕规范反而会撕裂版面关系。

## 3. 题材 → 风格映射

### 3.1 映射的输入是什么

风格选择不能靠"随机轮换避免重复"。当前 `NewsTemplatePicker` 的实际机制是：**模型从候选里选 + 最近 2 款被硬排除（`BLOCK_LIMIT = 2`）+ 失败退回"最久未用"**——这是**轮换**，不是**叙事**。而素材侧已经有一套叙事分类：

- **栏目**（`Column` 枚举，5 常设 + other）：科技竞争力 / 全球市场 / 商业观察室 / 趋势解码 / 全球数据图鉴 / 其他。
- **叙事类型**（`docs/plans/2026-11-19-data-board-story-plan.md` §6，已设计未实现）：`counter_intuitive` 反常识 / `numeric_contrast` 数字反差 / `trend_reversal` 趋势反转 / `rank_competition` 排名竞争 / `time_change` 时间变化 / `problem_evidence_reveal` 问题—证据—揭示。
- **数据形态**（`dataset/1` 的 `shape`）：`wide` / `long` / `rows` / `geo`（`geo` 目前无图表模块，`chartFor` 返回空串，`DatasetScriptContract:54-61`，**不可渲染**）。
- **图表模块**：`wide→line`、`long→race`、`rows→bars`（`stacked` / `multiline` / `radar` 渲染端支持，但 `chartFor` 目前不产出）。

### 3.2 映射表（主规则：叙事类型 → 风格）

**判定顺序：叙事类型优先于栏目。** 理由：风格决定的是"观众用什么姿态看"，叙事类型决定"这条片子要观众做什么"；栏目只决定"口径与禁语"，不决定画面语法。

| 叙事类型 | 观众要做的动作 | **推荐风格** | 理由（落到画面） | 可用形态 |
|---|---|---|---|---|
| `counter_intuitive` 反常识 | 「等等，跟我想的不一样」 | **B 数据调查** | 需要"异常点被圈出来、其余退场"的画面语法；A 的播报条装不下怀疑，B 的引线 + 焦点圈点天然适合"指认一个点" | wide / long / rows |
| `problem_evidence_reveal` 问题—证据—揭示 | 「一个问题，两个证据」 | **B 数据调查** | 一屏一证据、慢节奏、可反复回到同一张图——B 的"图表是物证"定位正对此 | 全部 |
| `trend_reversal` 趋势反转 | 「方向变了」 | **C 动态数据解释** | 反转需要**整条曲线**的可见性（不是某一点），C 是唯一把图当主角、且用 `focus-link` 连首末的风格 | wide / long |
| `numeric_contrast` 数字反差 | 「两个数放一起才有意思」 | **C 动态数据解释** | 需要"关系"而不是"某一点"；C 的 KPI + 曲线 + 口径行同屏，能把两个数并置 | 全部 |
| `rank_competition` 排名竞争 | 「谁在前面、差多少」 | **A 专业新闻** | 排名是**快照播报**（`rows` → `bars`），A 的下三分之一条 + 榜首数字是最像"榜单快讯"的形态；C 也可，但需先定"名次是不是热点" | rows / long |
| `time_change` 时间变化 | 「这段时间发生了什么」 | **A 专业新闻** | 时间跨度是播报口径（"本区间共 N 期"），A 的快节奏 + 密信息适合"区间盘点" | wide / long |

### 3.3 映射表（辅规则：栏目 → 风格倾向）

只在**叙事类型缺失或并列**（例如当前 story/1 尚未落地，风格选择只能拿到"栏目 + 形态 + 信号强度"）时使用。规则按下列优先级从上到下命中，命中即止：

| 优先级 | 条件 | 风格 | 说明 |
|---|---|---|---|
| 1 | 形态 = `rows`（当期榜单快照） | **A** | 榜单是播报物，不是调查物 |
| 2 | 栏目 = 全球市场（market）且 `cadence ∈ {daily, weekly}` | **A** | 行情播报有天然的播报语气与禁语要求（不构成投资建议） |
| 3 | 栏目 = 商业观察室（business） | **A** | 市值排名口径要求"当日汇率折算"，播报条放得下 |
| 4 | 栏目 = 趋势解码（trend） | **C** | 长序列、指数走势、要看的是曲线 |
| 5 | 栏目 = 科技竞争力（tech） | **C** | 榜单 + 对比混合，C 的高密度最省屏数 |
| 6 | 栏目 = 全球数据图鉴（atlas） | **B** | 跨年度、跨国对比、口径与年份必须说清 → 慢节奏 + 大留白 |
| 7 | 形态 = `geo` | **B** | `geo` 目前无图表模块；B 是三套里最不依赖图表的一套（"图表是物证"而非"图表是主角"），是未来接地图模块最自然的一端 |

### 3.4 明确的反模式（本设计拒绝的做法）

| 反模式 | 为什么拒绝 |
|---|---|
| 「今天用 B，明天用 C，后天用 A」 | 风格变成噪声，观众认不出栏目；`NewsTemplatePicker` 现有的"排除最近 2 款"就是这个逻辑，必须在 story 落地后**让位于叙事判定**，只保留作 tie-break |
| 「同一栏目固定一套风格」 | 栏目口径 ≠ 叙事类型。全球市场里"区间下行"（A）与"意外反转"（B）应不同 |
| 「按数据形态硬绑风格」 | `wide→line` 是渲染契约，不是叙事契约。`wide` 同时能承载 A 的播报与 C 的解释 |
| 「让风格随标题钩子类型走」 | 钩子类型（数字反差 / 疑问悬念 / …）是**文案层**，与画面语法无必然关系；`DatasetTitleAuthor` 的 `kind` 目前被丢弃是对的 |
| 「三套都排一遍再挑」 | 生成成本 ×3，且风格选择退化成装饰决策 |

### 3.5 与现有 `NewsTemplatePicker` 的衔接点（设计说明，不改代码）

- 选模板的入口是 `NewsTemplatePicker.pick(title, summary, line)`，候选来自 `templateCatalog()` 并按 `supportedLines` 过滤；三套数据模板都声明 `DATA_BOARD`，所以它们已经在同一候选池里。
- **风格选择 = 模板选择**（一个模板一个风格键，`template.json` 的 `style` 字段带 `key/name/label/role`）。因此上文的映射表落到实现上，就是"选哪一个 `news-data-*` 模板"。
- 落点建议（属下一轮实现，本轮不改）：在 `styles.json` 的每个风格条目上增加 `narratives: [...]` 与 `columns: [...]` 两个数组，作为**模型选模板提示词里的可读依据**（`NewsTemplatePicker.prompt()` 目前只把 `description` 给模型看）；并在 `pickFrom()` 里把"排除最近 2 款"从**硬排除**降级为**同叙事类型内的 tie-break**。
- 注意 `styles.json` 的 `role` 字段（"热点新闻、重要事件、权威信息解读"等）目前**只用于前端预览**，不参与选模板（`NewsProductionDomain.TemplateStyle` 注释明说"风格只用于展示与前端预览，不参与选模板"）。所以新增映射字段是扩展既有结构，不是改语义。

## 4. 三套风格各自适合什么题材（可读的版本）

给非工程同学看的版本：

**A 专业新闻** —— 适合「**现在**发生了什么」。
- 典型：期货持仓周报、指数今日收盘、市值榜单快照、某项指标的本期读数。
- 看点：快、准、可播报。像新闻联播里的数据条。
- 不适合：需要观众跟着推理的题（信息量不够）、需要长时间停留在一个点上慢慢看的题。

**B 数据调查** —— 适合「**这件事不对劲**」。
- 典型：某项价格连跌五期创区间新低、某国家的指标反常地落后、两年间某个比例的突变。
- 看点：慢、留白、每次只圈一个点。像纪录片的"看证据"段落。
- 不适合：平铺直叙的数据速览（会显得拖）、需要在一屏里同时比较七八个数的题。

**C 动态数据解释** —— 适合「**这组数字拆开看是这样的**」。
- 典型：一条长序列的走势解剖、指标之间的相对变化、榜单与趋势的结合。
- 看点：信息密度高、图表占主视区、可以停下来自己读图。
- 不适合：只有一个数字的极简陈述（画面会太空）。

## 5. 差异落到可实现的层面

分层原则：**能用令牌表达的，不要动 JS；能用版式 CSS 表达的，不要动共享 `chart.css`；实在需要改行为的，改动必须落在共享文件里且对三套都有意义**（否则又会长成三份真相）。

| 层级 | 位置 | 能表达什么 | 例子 | 破坏风险 |
|---|---|---|---|---|
| **L0 令牌** | `_shared/tokens/<style>.css` | 颜色、字号、字距、时长、缓动、栅格、颗粒、圆角、内外边距 | 三套的 `--fs-*`、`--dur-*`、`--ease-*`、`--rule-width`、`--grain-opacity` | 极低。但**注意 `--accent` 不在这里**（由 HyperFrames 从 composition 的 color 变量注入，手写会冲突——三份令牌文件的头部都写了这条） |
| **L1 版式 CSS** | `layouts/<style>/<layout>.css` | 版面骨架、场景区形态、**以及覆盖 `chart.css` 的图表外观** | A 把 `.scene` 做成通栏带；B 把 `.series-area` 覆盖为透明、`.series-line` 覆盖为 4px；C 保留面积 | 低。**因为版式 CSS 排在 `chart.css` 之后，覆盖是合法的**（`build-templates.mjs:211-221`） |

## 6. 在现有生成器与 LOCK 机制下落地

### 6.1 现状：改一个令牌会发生什么

```
改 _shared/tokens/news-broadcast.css
   └→ node data/tools/build-templates.mjs --template news-data-broadcast-9x16
        ├→ 重写 index.html / template.json / index.motion.json
        └→ writeManifest()：重算 assets-manifest.json（逐文件 sha256）
             └→ 重写 LOCK.json（assetManifestSha256 = sha256(assets-manifest.json)）
```

`build-templates.mjs` 的 `writeManifest()`（`:340-372`）**自动重算并重写 `LOCK.json`**，因此「改了样式但没更新锁」不会发生——`--check` 模式（`:414-427`）会比对三个生成物，`--verify` 还会跑 `hyperframes check`。

### 6.2 但有一个真实的可重放风险（必须写进流程）

`assetsGate`（`NewsProductionPipeline:576-590`）拿**冻结输入里的** `LOCK.json` 值（`input.path("assets")`，在认领时冻结进 `FrozenContext`）与**当前模板目录实算的哈希**比对：

```java
boolean manifestMatched = manifestSha.equals(locked.path("assetManifestSha256").asString());
if (!manifestMatched || !fontMatched || !templateMatched) {
    throw new HeronBusinessException(503, "news_assets_drifted", "…与模板目录的 LOCK.json 声明不一致");
}
```

而 `lockedAssets(templateKey)` 是**认领时**从模板目录读的 LOCK 值（`NewsProductionDomain:398-424`），并被写进冻结快照。

> **因此：任何改动 `index.html` 的操作（改令牌、改版式、改生成器、改骨架）都会让「该模板上已冻结的历史版本」在下一次重跑时命中 `news_assets_drifted`（503），无法重放。**
> 这不是 bug，是冻结契约的正确行为——但它是一条**运维事实**，必须进入改动流程。

### 6.3 因此本设计的落地流程约定

1. **视觉改动一律走「新模板目录 + 新 key」，不原地改旧目录。**
   新 key 例如 `news-data-broadcast-v2-9x16`（须匹配 `[a-zA-Z0-9_-]{1,80}`，`NewsWorkServiceImpl:324`）。理由：旧目录与它的 `LOCK.json` 原样保留 → 历史冻结版本仍可重放；新目录自带新的 `LOCK.json` → 新版本用新哈希。
   代价：模板目录数翻倍（现在 15 个目录），且 `availableTemplates()` 会把新旧都列为候选（`:429-447`）→ 需要**在候选过滤里显式排除被取代的旧 key**。这一条属实现改动，本轮只记录。
2. **如果确实要原地改旧目录**（例如纯 bug 修复），流程必须是：
   ```
   node data/tools/build-templates.mjs --template <key>     # 重生成
   node data/tools/build-templates.mjs --check --template <key>   # 确认无漂移
   node script/tools/template-lock.mjs data/templates/<key>      # 重生成 LOCK（与生成器双写，须一致）
   ```
   并接受：该 key 的历史冻结版本从此不可重放，需在发布记录里标注。
   注意 `build-templates.mjs` 与 `script/tools/template-lock.mjs` **都会写 `LOCK.json`**（前者内联在 `writeManifest()`，后者是独立脚本），两者必须产出同一份内容；本设计建议**统一只认生成器**（它顺带保证 `assets-manifest.json` 与 `LOCK.json` 自洽），把 `template-lock.mjs` 降级为「只用于非生成器管理的目录」。
3. **改 `chart.css` / `focus.js` / `motion.js` / `skeleton.html` 等共享文件 = 改全部 15 个模板**。每个模板的 `index.html` 都会变 → 每个模板都要重新生成 + 重新锁 + 全部历史冻结版本不可重放。**这是本设计里最贵的操作**，必须：
   - 单独一次提交，commit message 写明「影响全部模板的视觉行为变更」；
   - 跑完整 `node data/tools/build-templates.mjs --verify`（逐模板 `hyperframes check`）；
   - 对三套数据模板各出一张联络表（contact sheet）人工比对，确认 A/B/C 的签名结构没被新行为破坏。
4. **只改 `_shared/tokens/<style>.css`（L0）** 是最便宜的操作：只影响一个模板的 `index.html` → 只影响一个模板的哈希。若该风格尚未有历史冻结版本，**可以原地改**（当前三套数据模板的生产历史尚短，是本轮做视觉差异化的最佳窗口）。
5. **只改 `layouts/<style>/<layout>.css`（L1）** 与 L0 等价：同样只影响一个模板。

### 6.4 落地顺序（建议）

| 批次 | 内容 | 层级 | 影响模板数 | 风险 |
|---|---|---|---|---|
| 1 | 三套风格各补齐一套**语义色令牌**（图表标注色、焦点压暗强度、图表线宽、面积透明度），全部走 L0/L1 | L0+L1 | 1（逐套） | 极低。**但"焦点压暗强度"必须等 L3 才生效**，先只落令牌不接线，或与批次 2 同做 |
| 2 | `focus.js` 把两个写死的压暗常量改为读令牌；`chart.js` 的极值标注色改为读令牌（默认值保持现状） | L3+L4 | 全部 15 | 中。改动小但面广，**必须 `--verify` 全跑 + 三套联络表比对** |
| 3 | `chart.js` 把图表内字号从 JS 反推改为 CSS 令牌驱动，消除 16px 违规 | L4 | 全部 15 | 中高。影响所有图表模块的可读性，需逐模块（line/bars/race/stacked/multiline/radar）验证 |
| 4 | 三套的动效动作差异化（遮罩 / 揭示 / 重音） | L4（`motion.js`） | 全部 15 | 高。**建议先只在一套上试点**（推荐 B，因为它最慢、最需要动作区分度），跑通再推广 |
| 5 | 风格映射落到 `styles.json` + `NewsTemplatePicker` | Java | 0（模板） | 中。改选版式逻辑，会改变线上出片分布，需与 story/1 一起排期 |
