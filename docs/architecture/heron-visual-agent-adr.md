# ADR · 视频线 Agent 自主创作架构（V1）

> **【已否决 2026-11-26】** 本 ADR 同日晚间被《Heron 视频导演系统（V2）》取代：
> `docs/architecture/heron-video-director-adr.md`。否决点：模板中心路线（配方选卡 +
> 片级锚定 + 渲染层不组件化）整体推翻，转 AI 视频导演系统。本文保留作决策记录，不再执行。

> 2026-11-26 定案。背景：视频线现状是确定性 Java 流水线（`NewsProductionPipeline`），写稿为 LLM 调用，
> 但选模板、场景构图、动效、素材、节奏全是写死规则，画面上限被模板锁死。本 ADR 定义 Agent 接管
> 内容决策的边界与机制，适用于**整个视频产品线**（新闻线两条子线及后续新线）。
> 决策过程为对抗式评审（grilling），六轮修正，最终共识见下表。

## 一、总架构：三层混合

**Java 流程控制 + Agent 内容决策 + 工具执行。**

| 层 | 谁负责 | 内容 |
| --- | --- | --- |
| 流程控制 | Java（现有 Pipeline/闸门体系） | 状态机、任务依赖、重试、超时、成本预算、闸门、持久化 |
| 智能决策 | Agent（AgentScope Java 运行时） | 叙事设计、观点提炼、分镜规划、锚点提议、质量诊断 |
| 工具执行 | 工具层（hyperframes / ffmpeg / TTS / OSS） | 搜索、渲染、合成、素材，Java 调度 |

- Agent 提交**结构化决策**（沿 `StoryPlanContract` v2 模式），Java 校验后推进；
- Agent 可建议重做某镜头，但重试次数、预算、失败原因由 Java 控制；
- 所有决策走 JEV / ToolCallLedger 留痕，闸门必须能答「哪条闸 + 哪段输入 + 为什么拒」；
- 视频 agent 沿用调研线受控模式（参照 `ResearchAgentFactory` 显式禁用动态 skill 的取向）。

**否决两个极端**：Agent 全权控制产线（不确定、成本失控、故障难恢复）；Java 全写死（退化为
「通用模板换文字」，产出不了有观点的视频）。

## 二、自由度契约

**叙事：Agent 全自主。** 故事结构、叙事顺序、镜头数量、时长、旁白文案、镜头间关系全部自主决定，
Playbook 是可选参考经验、不是必选菜单，Agent 可组合多个 Playbook 或完全自主设计。禁止
「选题 → 匹配模板 → 模板决定脚本分镜」这条旧路径。

**视觉：场景级词汇表。** 每个镜头的视觉从「场景类型 × 构图 × 动效」配方库选择，配方是**经过验证
的视觉组合**，不是三维度笛卡尔积（不是所有场景都支持所有构图动效）。遇到词汇表覆盖不了的镜头，
Agent 可提新视觉方案走人工评估，不允许假设未实现的能力存在。

**渲染层：V1 不组件化。** 现有 7 套整体式 Composition 继续作为渲染实现。组件库（任意拼装图表/
字幕/转场/镜头运动）是建工路线图，由真实需求触发（多套模板重复实现同一场景、跨模板复用成高频、
新增视觉能力要改多套模板），不是 V1 前置条件。

## 三、核心机制：三个概念 + 片级锚定

| 概念 | 是什么 | 存储形态 |
| --- | --- | --- |
| `Composition` | 整条视频的视觉设计语言（现 `data/templates/**`） | 现状不动 |
| `VisualRecipe` | 镜头级配方：场景类型、构图、动效、能力要求、时长约束、`agentHint`（给 agent 看的描述） | `data/recipes/*.json`，与模板实现**同库同提交** |
| `RendererBinding` | 配方 → 具体渲染实现的映射 | 配方 JSON 内声明，解析必须带 Composition 上下文 |

**片级锚定（V1 一致性方案）：**

1. 生产顺序：Agent 自主设计叙事 → **提议视觉锚点** → Java 校验 → 锁定 → Agent 在该 Composition
   的配方范围内逐镜头规划 → Java 带锚点上下文解析绑定 → 渲染。
2. 锚点选择 = **Agent 提议 + Java 校验硬约束**（目标平台画幅、业务线模板池、模板可用性）。
   视觉方向是内容判断，归 Agent；Java 只守硬边界。锚点提议在叙事设计之后、详细分镜之前。
3. `resolve(recipeId, compositionId, compositionVersion)`——绑定解析必须接受片级上下文，
   **不允许跨模板混拼**。同一配方在多套模板有实现时，本片只用锚定模板那份。
4. 锚定 Composition 一旦进入正式渲染即固定版本；中途换锚点 = 重新评估整片镜头兼容性，不能只换一个镜头。
5. 当前 Composition 不支持某镜头时：Agent 改镜头方案 / 用同模板替代配方 / 提交人工，不允许偷偷换模板。
6. 演进方向：`VideoDesignProfile`（片级设计令牌：色板/字体/间距/动效曲线）。配方声明 tokenRequirements
   而非自带整套设计语言；等足够多实现支持统一 Profile 后再放开跨模板组合，届时一致性由令牌保证。

## 四、知识送达：不用 AgentScope Skills（V1）

**结论：V1 不启用 Skills，不引入 GitSkillRepository，也不预装 ClasspathSkillRepository。**

| 资产 | 送达方式 |
| --- | --- |
| VisualRecipe | 结构化 JSON，Java 加载并**先按锚定模板过滤**，只把合法配方喂给 Agent 选择 |
| Playbook | Markdown 文档，Java 按选题与阶段挑选相关内容注入 prompt |
| 能力说明 | 配方 JSON 的 `agentHint` 字段，机器字段与 agent 描述同源 |

- 「Java 先过滤再喂」把非法场景类型从「选了被闸拒、重选烧 token」变成「根本不出现在选项里」；
  Java 侧输出校验仍保留作兜底（LLM 仍可能输出错误 ID）。
- Skills 解决的是大量知识的组织与按需发现，不直接让视频变好。V1 的 Playbook 只有几份、配方由
  Java 过滤后枚举，注入式送达完全够用。
- **重新评估触发条件**（满足其一即重议，届时优先 Classpath——随 JAR 同版本发布回滚）：
  Playbook 多到 Agent 需要自主发现并按需阅读；或多个 Agent 需要独立加载、独立维护不同领域知识库。
- 即使将来启用，Skill 只提供指导；模板修改、渲染配置、Git 写入等生产权限始终由 Java 控制。

## 五、表现数据反哺

沿三任务书 C 单缺口（`MetricInsightAnalyzer` 只出报表不回灌）演进：

```
发布 → 表现采样 → 识别有效叙事/视觉模式 → 生成 Playbook/VisualRecipe 优化建议
     → 人工审核或实验验证 → 更新经验库 → 下一轮创作参考
```

不自动修改模板、不自动发布新配方；单条爆款不构成证据，需足量样本并扣除选题/时段/受众差异。

## 六、V1 落点与排期

| 步骤 | 内容 |
| --- | --- |
| 第一落点 | **数据看板线**增量改造：`StoryPlanContract` v2 演进为完整决策链（锚点提议 → 校验 → 配方过滤 → 分镜选配方），渲染层零改动，跑真实期数积累表现数据 |
| 第二步 | **文稿解说线**复用同一机制，换模板池即接入（顺带解决其锚点空间只有 1 套的现状） |
| 建工主线 | 维护配方库与 Playbook 库；新能力 = 加一张配方卡 + 模板场景实现，同一笔提交 |

## 七、一句话契约

**叙事由 Agent 自主创造，视觉由能力词汇表约束（片级锚定，不跨模板混拼），渲染由现有 Composition
承载，知识由 Java 过滤注入（不用 Skills），经验由生产反馈持续积累。**
