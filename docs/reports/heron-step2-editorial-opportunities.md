# 步骤 2：数据机会接入候选池与总编辑

**日期：** 2026-11-13
**前置：** `docs/plans/2026-11-13-data-opportunity-discovery-plan.md` 第七章「步骤 2」
**上游：** `heron-step1-data-opportunity.md`、`heron-signal-semantics.md`、`heron-source-health.md`

---

## 一、目标

在步骤 1 里，数据机会只是一个能查的表——总编辑看不到它，生产也不读它。这一步把机会接进决策链。

验收：**同一批数据下，总编辑能说出「为什么今天做这条」，而且理由里有具体数字。**

---

## 二、改动

### 2.1 候选池多了第六条线

`EditorialCandidatePool` 增加 `opportunities`，一并进 `PoolDigest` 的 hash。机会参与摘要的字段只有决策真正会读的：分数、标题、信号 JSON、观察时间。

### 2.2 拆掉「没有新闻就不产出」

原来的 `candidatePool()` 在没有白名单新闻候选时直接返回空池——**在查数据源之前**。后果是：没有新闻的那天，连数据看板也一条都不产，而失败原因还写成 `no_candidate`。

现在改为：

| 条件 | 结果 |
|---|---|
| 新闻候选空 + 机会空 | 空池，槽位 `skipped` |
| 新闻候选空 + 有机会 | **数据看板照常产出** |
| 新闻候选有 + 机会空 | 走解说线 |
| 都有 | 总编辑按提示词判断 |

机会的读取是「24 小时内、状态 new、按分数倒序、取前 10」。读失败按「没有机会」处理——附属查询不能把整个槽位打挂。

### 2.3 总编辑第一次看到数字

`Pools` 增加 `opportunities`，每条的 label 是：

```
Frankfurter 近 7 日 -2.39%，创窗口新低（3.6σ）（同向 7 个源），分 69.94
```

`Decision` 增加可选的 `focusOpportunityId`，与 `focusCandidateId` 同级：模型可以点名某条机会，校验规则同样是「必须真在池子里」。

`daily-editor.md` 重写：

- 新增「数据机会怎么看」一节，说明变化 / 偏离 / 分数三个字段怎么用。
- 「默认走 DATA_BOARD」改成「有值得做的机会就走 DATA_BOARD」。
- 明确 `NO_PUBLISH` 的合法场景里加上「分数不高，只是有点变化」。

### 2.4 线内编辑直接锁源

`editDataBoard` 现在先看机会：

| 情况 | 行为 |
|---|---|
| 总编辑锁定了某条机会 | 用它绑定的 `source_key`，`digest=false` |
| 没锁定但有机会 | **取分数最高的那条** |
| 完全没有机会 | 退回旧的选源器（含速览轮换），旧路径不变 |

第二条是刻意加的：选源器拿到的题材是写死的 `"数据看板"`（Phase 0 已确认），它不可能比算出来的机会更懂今天。有机会时再问它一次等于把决策推翻。

### 2.5 决策留痕

`pool_json` 追加 `opportunities` 键和 `decision.focusOpportunityId`。

**原有四个键（`hotHeadlines` / `articleCandidates` / `dataSources` / `recentPublications`）一个字没动**——编辑策划页按这四个键直接解析，改了就白屏。新键平级追加。

## 三、影响面

| 面 | 影响 |
|---|---|
| 数据库 | 无迁移。机会表已存在（030） |
| API | 无变更 |
| 生产链路 | **行为变化**：有机会时数据看板不再走选源器；没有新闻但有机会时可以出片 |
| 前端 | 无需改动。`pool_json` 多一个键，编辑策划页不解析它 |
| 历史槽位 | 旧 `pool_json` 没有 opportunities 键，回放不受影响 |
| 解说线 | 不变：仍要求带正文的文章 |

## 五、未解决 / 验证不到

| 项 | 说明 |
|---|---|
| 未在真实槽位上跑过 | 需要 `auto-enabled: true` + 真实新闻源 + 一次真实分析。当前都是关的 |
| 机会与新闻同时存在时的选择质量 | 只能靠实跑观察；提示词已给出判断顺序，但没有真实样本 |
| `focusOpportunityId` 模型是否会用 | 提示词给了用法，模型可能始终不返回，退化为「取最高分」——两种情况都可用 |
| 暂无机会 ID 的独立列 | 追溯靠 `pool_json`；如果以后要按机会反查视频，需要给 `heron_auto_slot` 加列 |
| mysql 组仍未运行 | 池/摘要涉及 DB 的路径只有单测覆盖 |

## 六、风险

| 风险 | 说明 |
|---|---|
| **数据看板完全由机会驱动** | 有机会时不再走选源器。如果某天机会质量很差，数据看板会照做那条差机会——质量把控落在机会的阈值与合并上，不在这里 |
| 只取前 10 条机会 | 池子被截断；分数第 11 名以后的机会当天不可见 |
| 机会 24 小时窗口 | 分析没跑的那天，池里没有机会，行为退回改动前 |
| 提示词重写 | 总编辑的行为口径变了，需要实跑确认不会过度倾向 `NO_PUBLISH` |
